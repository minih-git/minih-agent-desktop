## 1. 目的

远程客户端让用户监督仍在自己电脑上运行的 Agent 工作，它不是第二个桌面端。
手机的使用场景短暂、易被打断，通常由推送通知触发，而且常常单手操作。现有页面
是为了端到端打通协议而做的：每种状态都正确暴露了，但呈现方式是一叠样式相同的
带边框卡片，加上桌面尺寸的文字按钮。本规范把同样的能力整理成一个完整的移动端产品。

## 2. 现状审查

依据已安装的 iOS 构建（Gateway `rc.hmini.org`，2026-10-19）和 `origin/main` 源码：

| 编号 | 问题 | 证据 | 影响 |
|---|---|---|---|
| D1 | 页面左右内边距为零，卡片和页头按钮贴到屏幕边缘 | `.app-safe-area` 是未分层 CSS，它的 `padding-left/right: env(...)`（竖屏 iPhone 上为 0）覆盖了分层的 Tailwind `px-3` / `px-2` | 看起来像坏了；文字贴着屏幕圆角 |
| D2 | 页头下方有一大块空白 | 同一个类同时用在 `header` 和 `main` 上：页头额外加了底部（Home 指示条）安全区，`main` 又加了一次顶部安全区，而且两者都替换掉了 `py-*` 工具类 | 刘海屏 iPhone 首屏浪费约 80 pt |
| D3 | 没有首次使用体验 | 空主机列表只有一句话，外加一张账户登录卡片 | 用户不知道该走哪条路，也不知道这个 App 是做什么的 |
| D4 | 两个主操作互相竞争 | “添加主机”（票据配对）作为唯一的实心按钮放在页头，更简单的账户登录却是下方的次要按钮 | 推荐路径看起来反而是次要的 |
| D5 | 所有界面都是同一种卡片 | 时间线消息、工具调用、授权、提示条、列表都用相同边框和圆角的 `Card` | 没有层级；对话读起来像表单 |
| D6 | 危险操作与普通操作同等权重 | “停止”和“中断”并排；每一行里“忘记”紧挨“打开” | 容易误触 |
| D7 | 用词不统一 | 简体中文同一事物同时叫“主机”和“电脑”；“回合”“幂等键”“票据”等协议术语直接展示给用户 | 显得技术化、未完成 |
| D8 | 视觉身份与桌面端脱节 | 使用偏蓝的 Tailwind slate 色板和 `#0b0f14` 启动页，而桌面端是中性灰体系 | 两个产品看起来毫无关联 |

无论本次重设计的其余部分如何推进，D1 和 D2 作为布局缺陷都要最先修复（第 6.1 节）。

## 3. 用户、任务与原则

主要用户：拥有一台或多台运行 Minih 的电脑、此刻不在电脑前的人。按频率排序的任务：

1. 处理 Agent 正在等待的事情——工具授权或提问——通常直接从通知进入。
2. 扫一眼工作仍在运行、已完成还是已失败。
3. 引导：给运行中或空闲的会话发送后续消息。
4. 停止跑偏的运行。
5. 一次性连接这台手机（账户登录或配对票据）。
6. 偶尔管理电脑：刷新、重新申请、忘记。

设计原则：

- **决策优先。** 任何等待用户处理的内容，在它出现的页面上都是最醒目的元素，并且拇指可及。
- **默认安静。** 正常状态不出现提示条，也不使用颜色。颜色只用于状态语义，而且从不单独
  出现（总是配合文字或形状）。
- **每屏一个主操作。** 主操作是固定在底部拇指区的全宽实心按钮；其余操作为次要、文字
  按钮，或收进底部弹层。
- **危险操作多隔一步。** 危险操作放在带确认的操作弹层里，永远不和主操作相邻。
- **与桌面端同一家族。** 中性灰界面、墨色主按钮、沿用桌面端的状态色和同一套图标库。
- **如实反映连接状态。** 用户始终知道所见内容是否实时；在主机确认之前，App 绝不暗示
  操作已经生效。

## 4. 信息架构与导航

导航是单一的入栈结构，没有底部标签栏：产品只有一条层级，标签栏会在时间线页面上浪费垂直空间。

```text
启动
 ├─ 没有电脑 ─▶ S1 连接
 │               ├─ S2 账户登录 ─▶ S2a 申请设备 ─▶ S2b 等待确认 ─▶ S2c 结果
 │               └─ S3 配对票据
 └─ 已有电脑 ─▶ S4 我的电脑
                 ├─ （+）操作弹层 ─▶ S2 / S3
                 ├─ （⋯）电脑弹层：刷新 · 重新申请 · 忘记
                 └─ S5 会话列表 ─▶ S6 会话（时间线 + 决策区 + 输入框）
点按推送 ─────▶ S6 会话，下方恢复 S4 ▸ S5
```

| 编号 | 页面 | 入口 | 替代 |
|---|---|---|---|
| S0 | 启动与启动失败 | App 启动 | `BootFailure` |
| S1 | 连接 | 本机没有已保存的电脑 | 空的 `HostsScreen` |
| S2 | 账户登录流程 | S1 或（+）弹层 | `AccountScreen` |
| S3 | 配对票据 | S1、S2 的备选路径或（+）弹层 | `PairScreen` |
| S4 | 我的电脑 | 启动时至少有一台电脑 | `HostsScreen` |
| S5 | 某台电脑的会话 | 点按在线电脑 | `SessionsScreen` |
| S6 | 会话 | 点按会话或推送 | `SessionScreen` |
| S7 | 弹层与对话框 | 按上下文出现 | 行内确认 |

返回行为：页头返回按钮和 Android 实体返回键都返回上一级（沿用现有 `previousScreen`）；
iOS 另外通过 WebView 的标准历史手势支持边缘右滑返回，但仅限不与代码块内横向滚动冲突的情况。

## 5. 视觉系统

### 5.1 颜色令牌

色值沿用桌面端令牌（`apps/desktop/src/styles/tokens.css`），让两个产品看起来属于同一家族。
由于远程客户端不引入桌面端 CSS，命名使用 `--rm-` 前缀。

所有状态色与桌面端完全一致，包括“等待决策”使用紫色（负责人于 2026-10-19 确认），
让需要用户处理的会话在两端看起来一样。

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--rm-bg-page` | `#f3f3f3` | `#181818` | 分组内容后面的页面背景 |
| `--rm-bg-surface` | `#ffffff` | `#212121` | 分组列表、卡片、输入框 |
| `--rm-bg-raised` | `#ffffff` | `#282828` | 弹层、浮动胶囊、深色模式下的用户消息气泡 |
| `--rm-bg-inset` | `#ededed` | `#0d0d0d` | 代码与工具输出、浅色模式下的用户消息气泡 |
| `--rm-text-primary` | `#1a1c1f` | `#ffffff` | 标题与正文 |
| `--rm-text-secondary` | `#1a1c1f` 74% | `#ffffff` 70% | 辅助文字、行副标题 |
| `--rm-text-muted` | `#5d5d5d` | `#9b9b9b` | 说明、时间戳、分组标题 |
| `--rm-text-faint` | `#afafaf` | `#5d5d5d` | 占位符、禁用图标 |
| `--rm-separator` | `#1a1c1f` 8% | `#ffffff` 8% | 行分隔线、细边框 |
| `--rm-accent` | `#1a1c1f` | `#ffffff` | 主按钮、发送按钮、焦点环 |
| `--rm-on-accent` | `#ffffff` | `#1a1c1f` | 主色上的文字与图标 |
| `--rm-running` | `#c2410c` | `#ff8549` | 运行中 |
| `--rm-decision` | `#7c3aed` | `#c27aff` | 等待授权或回答（桌面端 `--ds-purple`） |
| `--rm-on-decision` | `#ffffff` | `#1a1c1f` | `--rm-decision` 底色上的对勾和图标 |
| `--rm-success` | `#00802f` | `#40c977` | 在线、已完成 |
| `--rm-error` | `#d42a26` | `#ff6764` | 失败、已撤销、危险操作 |
| `--rm-link` | `#1c64c8` | `#63a8f8` | 仅用于消息正文里的链接 |

提示条和标签的语义底色为对应语义色在 `--rm-bg-surface` 上叠加 10%（浅色）或 16%（深色）。
主题跟随系统外观，App 内不提供主题切换。`theme-color` 和原生启动页在两种外观下都使用
`--rm-bg-page`（替换 `#0b0f14`）。

### 5.2 字体排版

字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC",
"Hiragino Sans GB", "Segoe UI", Roboto, "Noto Sans CJK SC", "Microsoft YaHei",
sans-serif`；等宽：`ui-monospace, "SF Mono", Menlo, Consolas, monospace`。
不打包网页字体（CSP 只允许同源字体，且系统字体对中文渲染最好）。

| 角色 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| 大标题 | 28 / 34 | 700 | 未滚动时的 S4 标题、S1 与结果页主标题 |
| 标题 | 17 / 22 | 600 | 导航栏标题 |
| 小标题 | 16 / 22 | 600 | 行标题、卡片标题 |
| 正文 | 16 / 24 | 400 | 消息、表单输入（16 px 可避免 iOS 聚焦时缩放） |
| 说明 | 15 / 22 | 400 | 卡片和弹层里的解释文字 |
| 副标题 | 14 / 20 | 400 | 行副标题、状态行 |
| 脚注 | 13 / 18 | 400 | 分组标题、帮助文字、时间戳 |
| 标注 | 12 / 16 | 500 | 标签、徽标、排队计数 |
| 等宽 | 13 / 20 | 400 | 工具名、工具输出、票据和 key 输入框 |

所有字号用 `rem` 表示，以便跟随浏览器和系统的文字大小设置缩放。文字放大到 200% 时页面不得
出现横向滚动（代码块可以在自身内部滚动）。

### 5.3 间距、圆角与尺寸

| 令牌 | 取值 | 用途 |
|---|---|---|
| 基础网格 | 4 px | 所有间距都是它的倍数 |
| 页面边距 | `max(16px, env(safe-area-inset-left/right))` | 页面左右内边距 |
| 分组间距 | 24 px | 分组之间；分组标题与分组之间 8 px |
| 卡片内边距 | 16 px | 分组行与卡片 |
| 行高 | 单行 52 px，双行 64 px | 列表行 |
| 触控目标 | 最小 44 × 44 px | 所有可交互元素，包括图标按钮 |
| 控件圆角 | 12 px | 按钮、输入框、选项行 |
| 分组圆角 | 16 px | 卡片和分组列表 |
| 弹层圆角 | 20 px（顶部两角） | 底部弹层 |
| 气泡圆角 | 18 px，尾角 6 px | 用户消息气泡 |
| 内容宽度 | 最大 640 px，居中 | 横屏手机、平板、桌面浏览器 |

层级：浅色模式下，界面与页面只靠颜色区分（卡片不加阴影）。只有弹层、浮动的“新消息”胶囊和
底部输入区投影：浅色为 `0 -1px 0 var(--rm-separator), 0 8px 24px rgba(0,0,0,0.08)`，
深色只保留 1 px 顶部细线。

### 5.4 图标

与桌面端一致使用 Lucide（`07-ui-design-system` §7）：按钮和导航中 20 px、2 px 描边；行内
16 px、1.5 px 描边；空状态和结果页 48 px、1.5 px 描边。不用文字符号（`←`、`↻`）或 emoji
充当图标。图标默认 `--rm-text-secondary`；状态图标使用第 5.6 节的状态令牌。

### 5.5 动效

| 交互 | 时长 | 缓动 | 减弱动态效果时 |
|---|---|---|---|
| 按压反馈（透明度或缩放到 0.98） | 120 ms | ease-out | 仅透明度 |
| 提示条、标签、轻提示的出现与消失 | 200 ms | `cubic-bezier(0.2, 0, 0, 1)` | 立即切换 |
| 页面入栈与出栈（24 px 平移加淡入淡出） | 280 ms | `cubic-bezier(0.2, 0, 0, 1)` | 120 ms 交叉淡化 |
| 底部弹层打开与关闭 | 280 ms | `cubic-bezier(0.2, 0, 0, 1)` | 立即切换 |
| 状态点提醒 | 两个 1.6 s 周期后静止 | ease-in-out | 静止 |

只有表示正在进行的工作的指示器（流式回复、运行中的工具行、等待倒计时）可以在工作持续期间
一直动画，与桌面端 `07-ui-design-system` §4.5 的规则一致。

### 5.6 状态语义

电脑行、会话行、运行状态栏和时间线共用一套状态表达，且从不只用颜色传达状态。

| 状态 | 令牌 | 形状与动效 | 文案 |
|---|---|---|---|
| 在线 | `--rm-success` | 实心圆点 | 在线 |
| 离线或无法连接 | `--rm-text-muted` | 空心圆点 | 离线 |
| 运行中 | `--rm-running` | 实心圆点，呼吸两次；运行中的工具行显示转圈 | 运行中 |
| 等待决策 | `--rm-decision` | 实心圆点，脉冲两次 | 需要你处理 |
| 已完成 | `--rm-success` | 对勾 | 已完成 |
| 失败或已撤销 | `--rm-error` | 圆圈感叹号 | 失败 / 访问已撤销 |

## 6. 布局骨架

### 6.1 安全区（修复 D1 和 D2）

每条边的安全区只应用一次，由紧贴该边的元素负责，并且与常规内边距叠加——而不是替换常规内边距：

```css
/* 放在 @layer utilities 中，保证与 Tailwind 的先后顺序可预期 */
.rm-nav      { padding-top: env(safe-area-inset-top); }
.rm-gutter   { padding-left: max(16px, env(safe-area-inset-left));
               padding-right: max(16px, env(safe-area-inset-right)); }
.rm-dock     { padding-bottom: max(8px, env(safe-area-inset-bottom)); }
.rm-scroll-end { padding-bottom: calc(24px + env(safe-area-inset-bottom)); }
```

导航栏负责顶部安全区；底部固定区（输入框、决策区或底部操作按钮）负责底部安全区；没有底部
固定区的页面给滚动内容加 `rm-scroll-end`。`main` 永远不加顶部安全区。删除 `.app-safe-area` 类。

### 6.2 导航栏

- 顶部安全区下方高 44 px；背景为 92% 的 `--rm-bg-page` 加背景模糊；只有内容滚到其下方时
  才出现细分隔线。
- 左侧：返回按钮（chevron-left 图标，44 px 触控区，无障碍名称“返回”）。中间：标题（标题样式，
  单行，超长截断）。右侧：最多两个 44 px 图标按钮。
- S4 在滚动内容里使用 28 px 大标题，滚过之后收起为 17 px 的导航栏标题。
- 标题下可选一行副标题（脚注、弱化色），用于承载上下文，例如 S6 上的电脑名称。

### 6.3 底部固定区与键盘

底部固定区是页面列的最后一个子元素，吸附在底部。软键盘弹出时，固定区必须紧贴在键盘上方：
Android 和浏览器在 viewport meta 中使用 `interactive-widget=resizes-content`；iOS 使用
Capacitor Keyboard 插件的原生 resize 模式（决定 O2）。键盘动画过程中，时间线的滚动锚点
保持在底部。

## 7. 组件

以下组件替代现有 `Chrome.tsx` 中的基础组件，每个都是 `src/components/ui/` 下的小模块。

- **Screen（页面）**——包含导航栏、滚动区和可选底部固定区的列；负责第 6.1 节的安全区规则和
  640 px 内容宽度。
- **NavBar（导航栏）**——见第 6.2 节。
- **Button（按钮）**——变体：`primary`（主色填充）、`secondary`（界面色填充加分隔线边框）、
  `plain`（纯文字）、`destructive`（界面色上的错误色文字；只有在确认弹层里才使用错误色实心填充）。
  尺寸：`large`（52 px，全宽，用于唯一的主操作）、`medium`（44 px）、`icon`（44 px 正方形）。
  加载状态用转圈替换文字并保持宽度不变；禁用为 40% 透明度。
- **ListGroup / ListRow（分组列表 / 列表行）**——位于 `--rm-bg-surface` 上的内嵌分组列表，
  圆角 16，细分隔线从前置区域之后开始。行包含前置区域（状态点或 32 px 图标块）、标题、可选副标题、
  可选尾部（箭头、值或 44 px“更多”按钮）。可导航的行整行都是触控区。
- **SectionHeader（分组标题）**——脚注、弱化色、左右缩进 16 px，可选右侧纯文字操作。
- **StatusDot / StatusLabel（状态点 / 状态文字）**——见第 5.6 节。
- **Banner（提示条）**——导航栏下方的全宽横条，用于连接和数据新鲜度状态。色调分中性、运行中、
  错误三种，可带右侧操作。同一时间最多一条，优先级为错误、运行中、中性。
- **Callout（说明框）**——内容中的着色框，用于解释与周围内容相关的单件事（例如“这个问题只能在
  电脑上回答”）。
- **Sheet（底部弹层）**——带拖动条、标题和操作的底部弹层，用于操作菜单、确认和停止方式选择。
  可通过点按遮罩、下滑、Escape 或 Android 返回键关闭。
- **Toast（轻提示）**——在底部固定区上方显示 2.5 秒的临时确认（“已停止”“已忘记 MacBook”）。
  永远不用于需要用户处理的错误。
- **EmptyState / ResultState（空状态 / 结果页）**——48 px 图标、大标题或小标题、一段说明，以及
  最多一个主操作和一个纯文字操作。
- **Skeleton（骨架屏）**——`--rm-bg-inset` 色的静态占位块，带 1.2 s 透明度脉冲（减弱动态效果时
  取消），形状与被替代的行一致。
- **SecureField / TicketField（安全输入框 / 票据输入框）**——16 px 等宽文字；AccessKey 可切换
  显示；当 `navigator.clipboard.readText` 可用时，票据输入框右侧提供“粘贴”按钮。

## 8. 页面

### 8.1 S0 启动与启动失败

- 原生启动页：`--rm-bg-page` 背景上居中的 App 图标，分浅色、深色两种（用新背景色重新生成资源）。
- 启动页一直显示到 `boot()` 读完凭据为止；除非启动超过 600 ms 才在页面中央出现转圈，否则不显示
  第二个 WebView 内加载页。
- 启动失败（例如构建里没有写入 Gateway 地址）：结果页，显示警告图标、标题“Minih 远程无法启动”、
  失败原因，以及“需要重新构建此版本”的说明。不提供重试按钮，因为重试无济于事。

### 8.2 S1 连接

本机没有保存任何电脑时显示。

- 上半部分：64 px App 图标，大标题“在手机上接管你的 Agent”，说明“查看进度、批准操作、继续对话。
  任务仍在你的电脑上运行。”
- 三行简短的价值说明，配 20 px 图标：“批准或拒绝工具请求”“回答 Agent 的提问”“停止跑偏的运行”。
- 底部固定区（拇指区）：
  - 支持账户模式：主按钮（大）“使用 Minih 账户登录”，次按钮（大）“使用配对票据”。
  - 不支持或无法确定账户模式：只有主按钮（大）“使用配对票据”。
  - 账户模式探测进行中（通常不到 1 秒）：按钮位置显示骨架屏，避免布局跳动。
- 底部带锁图标的标注：“通过 rc.hmini.org 连接”（Gateway 主机名；浏览器版显示 `location.host`）。

### 8.3 S2 账户登录流程

在同一页面内完成的三步流程，导航栏下方有步骤指示（“登录 · 申请 · 确认”；当前步骤为墨色，其余弱化）。

**S2 登录。** 安全输入框“AccessKey”，可切换显示，帮助文字“仅用于本次登录，不会保存在手机上。”
底部固定区主按钮（大）“登录”，输入框非空时可用。纯文字链接“改用配对票据”。错误以“操作 + 原因”
显示在输入框下方。触发限流时按钮变为禁用的倒计时（“32 秒后重试”）。

**S2a 申请设备。** 一行紧凑的已登录信息（“已登录账户 1”，右侧纯文字按钮“退出登录”）。分组
“本账户下的电脑”列出每台主机，带状态点和一行合并了可用性与确认能力的副标题：“在线 · 可以批准
这台手机”“在线 · 需在本机逐台确认”或“离线”。“设备名称”输入框预填平台名称。主按钮（大）
“为这台手机申请访问”。如果没有任何电脑能确认，用错误色说明框替代列表说明，主操作改为“使用配对票据”。

**S2b 等待确认。** 居中显示：一个随剩余时间缩短的 96 px 圆环和 `mm:ss` 倒计时，小标题“请在你的
电脑上批准”，说明“在任意一台在线电脑上打开 Minih，批准“iPhone”。”下方是已收到请求的电脑列表。
底部固定区为纯文字按钮“取消”。临时读取失败时保持当前页面，显示中性提示条“正在重新连接…”，不重置圆环。

**S2c 结果。** 结果页的几种情况：

- 已收编：成功对勾，“已连接 3 台电脑”，主按钮“打开我的电脑”。
- 已超时：“没有电脑及时批准”，主按钮“重新申请”，纯文字按钮“使用配对票据”。
- 未送达（已批准但令牌未送达）：“已批准，但手机没能及时拿到访问权限”，主按钮“重新申请”。
- 已失效：“网关已不认识这个请求”，主按钮“重新登录”。
- 失败：“请求没有成功，手机上没有保存任何内容”，主按钮“重试”。

### 8.4 S3 配对票据

- 带两个编号步骤的说明框：“1. 在电脑上打开 Minih 的远程控制设置并生成配对票据（或运行
  `agent-host-cli remote-pair`）。2. 把票据粘贴到下方。”
- 票据输入框，三行，等宽，右侧有“粘贴”按钮。校验在粘贴和失去焦点时进行，而不是每次按键都校验：
  有效票据显示成功提示“票据格式正确 · 电脑 a1b2…”；无效票据在输入框下方显示现有的原因文案。
- “设备名称”输入框预填平台名称。
- 底部固定区主按钮（大）“配对”；加载状态为“正在配对…”。成功后清除票据（沿用现有行为），并打开
  新电脑的 S5。

### 8.5 S4 我的电脑

- 大标题“我的电脑”；右侧（+）图标按钮打开弹层：“使用 Minih 账户登录”（仅在支持账户模式时出现）
  和“使用配对票据”。
- 一个分组列表。行结构：左侧 32 px 笔记本图标块，右下角叠加状态点；标题为电脑名称；副标题为状态行；
  可打开时右侧显示箭头，另有一个 44 px“更多”按钮。
- 状态行：“在线”、“检查中…”（骨架状态点）、“离线 · Minih 未运行或电脑已休眠”、“尚未同步 ·
  下拉刷新”（严格模式主机为“请在那台电脑上批准这台手机”）、“访问已撤销”、“这台手机已不再持有访问
  权限”、“无法连接：原因”。
- 点按在线行打开 S5。点按其他状态的行会在行内展开说明框，给出解释和唯一的修复操作（“重新申请”
  “重新配对”），而不是跳转页面。
- “更多”弹层：“刷新”、“重新申请”（仅尚未同步时）、危险操作“忘记这台电脑”。“忘记”会再打开一个
  确认弹层，使用现有文案和实心危险按钮；成功后显示轻提示。
- 下拉刷新会重新探测所有电脑，取代每一行单独的刷新按钮。App 回到前台时也会刷新状态。
- 页脚标注：“Gateway rc.hmini.org · 访问权限保存在这台手机的钥匙串中”（原生版）或
  “……保存在安全 Cookie 中”（浏览器版）。

### 8.6 S5 会话列表

- 导航标题为电脑名称；副标题为电脑状态。
- 按分组显示，空分组不显示：“需要你处理”（状态 `waiting_permission`）、“运行中”（`running`）、
  “最近”（其余所有状态），每组内按时间倒序。
- 行：左侧 12 px 状态位（第 5.6 节），标题最多两行（会话标题；没有标题时显示“未命名会话”，而不是
  原始 ID），副标题为“3 分钟前”，非空闲状态再附加状态词（“已停止”“失败”）。相对时间使用
  `Intl.RelativeTimeFormat`；超过 7 天显示日期。
- 加载中：六行骨架屏。刷新：下拉刷新以及回到前台时刷新。
- 空状态：“这台电脑上还没有会话”，说明“在电脑上开始一个任务，它就会出现在这里。手机端不能新建会话。”
- 离线或加载失败：错误提示条带“重试”；保留上次加载的列表，但降低到 60% 透明度。
- 已撤销：结果页“这台手机的访问权限已被撤销”，主按钮“忘记并重新配对”。

### 8.7 S6 会话

**导航栏。** 返回按钮，标题为会话标题，副标题为电脑名称。

**连接提示条。** 实时连接时隐藏。`idle` → 中性“连接中…”；`retrying` → 运行中色“正在重新连接…”；
`exhausted` → 错误色“实时更新已停止”，右侧“重新连接”；`stopped` → 中性“已断开”；
`revoked` → 整个页面变为 S5 的“已撤销”结果页。`paused` 永远不显示，因为它只在页面隐藏时出现。
重新同步和回放不完整的提示使用中性提示条，沿用现有文案并按第 10 节改写。

**运行状态栏。** 运行进行中或排队时吸附在导航栏下方：状态点和文字（“运行中”“等你批准”“等你回答”
“已排队”），适用时显示排队标签（“排队 2 条”），右侧是次要中号按钮“停止”。点按“停止”打开弹层：

- “完成当前步骤后停止”——发送 `turn/stop`；主机完成当前助手回复或工具调用后结束本次运行。
- “立即停止”（危险操作）——发送 `turn/interrupt`；立即中止并取消排队中的运行。
- “取消”。

请求处理中时状态栏显示“正在停止…”，按钮禁用。运行结束后状态栏以 200 ms 动效收起，并用轻提示确认
（“已停止”“运行已完成”）。

**时间线。**

- 用户消息：靠右，最大宽度 85%，气泡为 `--rm-bg-inset`（浅色）或 `--rm-bg-raised`（深色），
  圆角 18，尾角 6 px。
- 助手消息：靠左，无气泡，全宽，正文样式并保留换行；链接使用 `--rm-link`。由子代理发出的消息前加
  一行小字“来自 {agent}”。
- 思考：折叠的展开项“思考”（脚注、弱化色、箭头）。
- 工具调用：内嵌容器中的紧凑行——状态图标（转圈、对勾或感叹号）、等宽工具名、一行摘要、箭头。
  展开后在 `--rm-bg-inset` 中以等宽 13 号字显示详情，可横向滚动，最高 320 px，带“显示全部”。
- 系统与上下文压缩提示：两条细线之间居中的脚注（“上下文已压缩”）。
- 被截短的内容用标注样式的“已截断”标签标出。
- 运行失败：在该次运行末尾显示错误色说明框“运行失败：原因”。
- 滚动：页面打开时定位到底部；只有当用户距离底部 120 px 以内时，新内容才自动跟随；否则在底部固定区
  上方出现带向下箭头的浮动胶囊“新消息”。
- 加载中：三个骨架气泡；空状态：弱化文字“还没有消息”。

**决策区。** 有待处理的授权或提问时，在输入框上方显示决策卡片。两者始终同时可见：卡片高度上限为
`clamp(200px, 100dvh − 400px, 55dvh)`，超出部分在卡片内滚动；因此在 568 pt 高的屏幕上，
时间线仍保留约 110 pt，输入框不会被挤出屏幕。它是页面上最醒目的元素。

授权卡片：

- 头部：盾牌图标和 `--rm-decision` 色标题（“需要你批准”“计划授权”“目标授权”）、风险标签
  （低风险为中性、中风险为运行中色、高风险为错误色）；有多条待处理时显示“1/3”和前后切换箭头。
- 内容：工具名（等宽）、摘要（正文，最多八行，带“展开”）、子代理来源，以及按整分钟显示的实时过期提示
  （“5 分钟后过期”），最后一分钟改为显示秒数（“45 秒后过期”）。已过期的请求变为只读并显示“已过期”。
- 操作：同一行两个等宽中号按钮——左侧次要危险按钮“拒绝”/“驳回”，右侧主按钮“允许一次”/“同意”。
  超过两个决定时纵向排列，主按钮在最后。
- 高风险：显示错误色提示“高风险——允许前请检查详情”，点按主决定会打开确认弹层，重复显示工具名和摘要
  （决定 O4）。
- 提交中：被点按的按钮显示转圈，两个按钮都禁用；失败信息显示在按钮下方，重试复用同一个请求标识（沿用现有行为）。
- 如果主机提供了“本会话内允许”，继续以弱化小字说明“本会话内允许只能在电脑上操作”。

提问卡片：

- 头部：问号图标和 `--rm-decision` 色标题“Agent 有个问题”。
- 有多个问题时逐个显示（“第 1/3 题”“下一题”“上一题”）；只有一个问题时直接显示。
- 选项为全宽 48 px 行，带单选或多选标记；多选题显示标注“可多选”。“跳过此问题”是纯文字按钮。
  最后一步显示主按钮“发送回答”。
- 没有选项的问题保留说明框“请在电脑上回答这个问题”。

**输入框。** 胶囊形输入框（圆角 22，`--rm-bg-surface`，分隔线边框），内含一到六行自动增高的文本域，
占位文字“给 Agent 发消息”，右侧是 36 px 圆形发送按钮，`--rm-accent` 底色加向上箭头图标。内容为空时
按钮禁用，发送中显示转圈。输入框上方的脚注提示：运行进行中时为“电脑正在运行，这条消息会排队。”，失败后
用 `--rm-error` 色显示“发送失败，点按发送重试。”已归档会话用弱化横条“该会话已归档，只能查看”替代输入框。

### 8.8 S7 推送入口

点按通知打开对应会话的 S6，下方恢复 S4 和 S5，并滚动到决策区。如果该决定已在其他地方处理，显示轻提示
“已在其他设备处理”，时间线展示处理结果。电脑未知或缺少 ID 时打开 S4（沿用现有行为）。

## 9. 通用行为

- **错误。** 每个用户可见的失败都写明操作和原因（沿用现有 `failureText`）。位置：字段错误放在字段下方，
  页面级失败放在提示条，操作失败放在该操作旁边。永远不用轻提示展示错误。
- **不做乐观更新。** 不提前显示成功。发出的消息以待确认气泡显示（60% 透明度、小时钟图标），直到主机回显；
  授权在主机处理完成前保持“提交中”。
- **回到前台刷新。** 回到 App 时重新探测电脑状态并恢复会话事件流（沿用现有 `visibilitychange` 处理）；
  只有恢复超过 800 ms 时才显示中性提示条“连接中…”。
- **无障碍。** 文字对比度至少 4.5:1，状态形状至少 3:1；每个图标按钮都有无障碍名称；每次入栈和出栈后焦点
  移到导航标题；运行状态变化通过礼貌型实时区域播报；新到的授权只播报一次；流式文本不逐字播报；选项行暴露
  单选或多选角色；所有手势（下拉刷新、下滑关闭）都有对应的按钮或菜单。
- **减弱动态效果与透明度。** 见第 5.5 节；设置 `prefers-reduced-transparency` 时，导航栏模糊改为不透明填充。
- **隐私。** AccessKey、票据和令牌不出现在结果页、轻提示或日志中；安全输入框关闭自动填充、自动纠正和拼写
  检查（保留现有行为）。

## 11. 响应式

- **竖屏手机（320–430 px）：** 采用上文布局。320 px 宽时两个决策按钮可以纵向排列。
- **横屏手机：** 内容宽度 640 px 居中；运行状态栏和底部固定区保持全宽；高度低于 480 px 时，S1 的品牌区
  移到操作按钮左侧。
- **平板（768 px 及以上）：** S5 和 S6 变为分栏（左侧会话列表 320 px，右侧会话）；S4 保持单列（第 4 阶段）。
- **桌面浏览器（H5）：** `--rm-bg-page` 上 640 px 居中的单列；不支持下拉刷新（改为在导航栏放刷新图标按钮）；
  悬停状态使用 4% 墨色叠加。

## 13. 验收标准

| 维度 | 用例 |
|---|---|
| 视口 | 320×568、375×667、390×844、430×932、844×390 横屏、820×1180 平板、1280×800 浏览器 |

## 14. 决定

已于 2026-10-19 确定；负责人授权按推荐方案选择。

| 编号 | 问题 | 决定 |
|---|---|---|
| O1 | 图标：给 `apps/remote-web` 添加 `lucide-react`，还是内联 SVG | 添加与桌面端同版本的 `lucide-react`；支持按需打包，不引入新供应商（第 1 阶段） |
| O2 | iOS 键盘处理 | 添加 `@capacitor/keyboard` 并使用原生 resize（第 3 阶段，与输入框一起）；否则底部固定区可能被键盘遮挡 |
| O3 | 助手消息中的 Markdown | 推迟到第 4 阶段；只支持安全子集（段落、列表、代码、链接），不支持 HTML 和远程图片。第 1–3 阶段显示纯文本和行内代码 |
| O4 | 高风险授权是否需要确认 | 仅 `high` 风险使用一个确认弹层；出于无障碍考虑不使用长按手势 |
| O5 | 简体中文用“电脑”替代“主机” | 面向用户的文案采用；协议、代码和规格仍保留“Host” |
| O6 | 跨电脑的“需要你处理”分组 | 推迟到第 4 阶段；仅在回到前台时轮询每台在线电脑的现有会话列表，不改协议 |
