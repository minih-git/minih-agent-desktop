## 1. 目的

远程客户端让用户监督仍在自己电脑上运行的 Agent 工作，它不是第二个桌面端。
手机的使用场景短暂、易被打断，通常由推送通知触发，而且常常单手操作。现有页面
是为了端到端打通协议而做的：每种状态都正确暴露了，但呈现方式是一叠样式相同的
带边框卡片，加上桌面尺寸的文字按钮。本规范把同样的能力整理成一个完整的移动端产品。

## 2. 现状审查

依据已安装的 iOS 构建（Gateway `rc.hmini.org`，2026-10-19）和 `origin/main` 源码：

| 编号 | 问题 | 证据 | 影响 |
|---|---|---|---|
| D1 | 页面左右内边距为零，卡片和页头按钮贴到屏幕边缘 | `.app-safe-area` 是未分层 CSS，它的 `padding-left/right: env(...)`（竖屏 iPhone 上为 0）覆盖了分层的 Tailwind `px-3` / `px-2` | 看起来像坏了；文字贴着屏幕圆角 |
| D2 | 页头下方有一大块空白 | 同一个类同时用在 `header` 和 `main` 上：页头额外加了底部（Home 指示条）安全区，`main` 又加了一次顶部安全区，而且两者都替换掉了 `py-*` 工具类 | 刘海屏 iPhone 首屏浪费约 80 pt |
| D3 | 没有首次使用体验 | 空主机列表只有一句话，外加一张账户登录卡片 | 用户不知道该走哪条路，也不知道这个 App 是做什么的 |
| D4 | 两个主操作互相竞争 | “添加主机”（票据配对）作为唯一的实心按钮放在页头，更简单的账户登录却是下方的次要按钮 | 推荐路径看起来反而是次要的 |
| D5 | 所有界面都是同一种卡片 | 时间线消息、工具调用、授权、提示条、列表都用相同边框和圆角的 `Card` | 没有层级；对话读起来像表单 |
| D6 | 危险操作与普通操作同等权重 | “停止”和“中断”并排；每一行里“忘记”紧挨“打开” | 容易误触 |
| D7 | 用词不统一 | 简体中文同一事物同时叫“主机”和“电脑”；“回合”“幂等键”“票据”等协议术语直接展示给用户 | 显得技术化、未完成 |
| D8 | 视觉身份与桌面端脱节 | 使用偏蓝的 Tailwind slate 色板和 `#0b0f14` 启动页，而桌面端是中性灰体系 | 两个产品看起来毫无关联 |

无论本次重设计的其余部分如何推进，D1 和 D2 作为布局缺陷都要最先修复（第 6.1 节）。

## 3. 用户、任务与原则

主要用户：拥有一台或多台运行 Minih 的电脑、此刻不在电脑前的人。按频率排序的任务：

1. 处理 Agent 正在等待的事情——工具授权或提问——通常直接从通知进入。
2. 扫一眼工作仍在运行、已完成还是已失败。
3. 引导：给运行中或空闲的会话发送后续消息。
4. 停止跑偏的运行。
5. 一次性连接这台手机（账户登录或配对票据）。
6. 偶尔管理电脑：刷新、重新申请、忘记。

设计原则：

- **决策优先。** 任何等待用户处理的内容，在它出现的页面上都是最醒目的元素，并且拇指可及。
- **默认安静。** 正常状态不出现提示条，也不使用颜色。颜色只用于状态语义，而且从不单独
  出现（总是配合文字或形状）。
- **每屏一个主操作。** 主操作是固定在底部拇指区的全宽实心按钮；其余操作为次要、文字
  按钮，或收进底部弹层。
- **危险操作多隔一步。** 危险操作放在带确认的操作弹层里，永远不和主操作相邻。
- **与桌面端同一家族。** 中性灰界面、墨色主按钮、沿用桌面端的状态色和同一套图标库。
- **如实反映连接状态。** 用户始终知道所见内容是否实时；在主机确认之前，App 绝不暗示
  操作已经生效。

## 4. 信息架构与导航

导航是一个入栈结构、两个根（仅原生构建，见
[ADR mobile-direct-gateway-chat](/adr/mobile-direct-gateway-chat)）：**对话**——
直连模型网关、不需要电脑在场的会话；以及**电脑**——现有的远程层级。根是一个底部标签，
因此原生构建只在两个根上显示带两个条目（对话、电脑）的根标签栏；浏览器构建既没有标签栏
也没有「对话」，保持今天的单一层级。时间线页面从不显示标签栏，所以它不在对话所在的页面
占用任何垂直空间。

```text
原生构建：一个栈、两个根（浏览器构建只保留「电脑」）

对话（根，D1）── 直连模型网关的会话，不需要电脑
 └─ 第一阶段为占位，直连页面发布前不进入

电脑（根，S1 空态 / S4）
 ├─ （+）操作弹层 ─▶ S2 / S3
 ├─ （⋯）电脑弹层：刷新 · 重新申请 · 忘记
 └─ S5 会话列表 ─▶ S6 会话（时间线 + 决策区 + 输入框）

设置（S8）── 从任一根的齿轮进入（第 15.7 节）
点按推送 ─────▶ 根切到「电脑」，S6 会话下方恢复 S4 ▸ S5
```

切换标签用替换（`replaceState`）落地根页面，返回从不在两个标签之间来回，
任一根上按 Android 返回即退出。点按电脑通知仍把根替换为「电脑」，并照旧
恢复 S4 ▸ S5 ▸ S6（第 8.8 节）。被推开的页面从不显示标签栏。

| 编号 | 页面 | 入口 | 替代 |
|---|---|---|---|
| S0 | 启动与启动失败 | App 启动 | `BootFailure` |
| S1 | 连接 | 电脑根的空态（第 17.3 节） | `ConnectScreen` 作为空态 |
| S2 | 账户登录流程 | S1 或（+）弹层 | `AccountScreen` |
| S3 | 配对票据 | S1、S2 的备选路径或（+）弹层 | `PairScreen` |
| S4 | 我的电脑 | 电脑根上有至少一台电脑 | `HostsScreen` |
| S5 | 某台电脑的会话 | 点按在线电脑 | `SessionsScreen` |
| S6 | 会话 | 点按会话或推送 | `SessionScreen` |
| S7 | 弹层与对话框 | 按上下文出现 | 行内确认 |

返回行为——一条规则、四条路径：页头返回按钮、Android 实体返回键、浏览器自带的返回、以及 iOS 边缘右滑，
全部通过 `previousScreen`（`src/lib/screen-stack.ts`）只退一级，因此不可能互相矛盾。

- **浏览器历史就是页面栈。** 每次向前导航写一条记录（`src/lib/screen-history.ts`：
  新层级用 `pushState`，已在显示的层级用 `replaceState`），`popstate` 时采用该记录自己声明的页面；
  旧版本写入、不带页面的记录则回退到 `previousScreen`。于是浏览器返回与 Safari 边缘手势都是
  “退一层”而不是“离开站点”，前进会回到它声明的记录，而用户进入时所在的那条记录是被替换而不是叠加的。
- **iOS 用客户端自己的边缘手势，而不是 WebView 的。** Capacitor 的
  `allowsBackForwardNavigationGestures` 故意不开：它返回时显示的是页面快照，而会话页是活的——
  有流式输出、有等你的决定、有正在跑的回合——快照与状态会当场不一致，而且这个手势驱动的是历史，
  会与应用自己的弹层状态打架。改由 `src/hooks/useEdgeSwipe.ts` 跟踪拖动并走同一条返回路径，
  于是只有一种行为需要推理。规则：起手必须落在左边缘 `EDGE_WIDTH`（20 px）以内；
  以纵向或向左为主的拖动原样放行，这正是时间线纵向滚动与代码块横向平移得以正常工作的原因；
  页面跟手位移，下层页面以三分之一距离做视差；松手时位移超过 `COMPLETE_FRACTION`（宽度 1/3），
  或是一次速度超过 `COMPLETE_VELOCITY` 且已移动至少 `MIN_FLICK_DISTANCE_FRACTION`（15%）的快滑，
  即完成返回，否则回弹。起手不在边缘、无处可退、或弹层打开时
  （存在 `[role="dialog"][aria-modal="true"]`），一律不拦截。
- **浏览器里不挂载 JS 手势。** 它本来就有边缘手势，两者同时运行会让一次滑动退两层。
- **推送打开会话时恢复栈（第 8.8 节），历史记录一起恢复**：打开所指会话时先写入该电脑的会话列表一条记录，
  再写入会话本身，因此从推送打开的会话右滑返回会落在那个列表上，而不是直接落到电脑列表。
- **启动与记住的根（第 17.3 节）。** 全新安装的原生端落在「对话」；对已保存过电脑的安装升级后的
  第一次启动落在「电脑」；之后应用重新打开上次选中的根——一个不含凭据的本地偏好
  （`localStorage` 键 `remote.last-root`）。冷启动从不恢复被推开的页面。

## 5. 视觉系统

### 5.1 颜色令牌

色值沿用桌面端令牌（`apps/desktop/src/styles/tokens.css`），让两个产品看起来属于同一家族。
由于远程客户端不引入桌面端 CSS，命名使用 `--rm-` 前缀。

所有状态色与桌面端完全一致，包括“等待决策”使用紫色（负责人于 2026-10-19 确认），
让需要用户处理的会话在两端看起来一样。

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--rm-bg-page` | `#f3f3f3` | `#181818` | 分组内容后面的页面背景 |
| `--rm-bg-surface` | `#ffffff` | `#212121` | 分组列表、卡片、输入框 |
| `--rm-bg-raised` | `#ffffff` | `#282828` | 弹层、浮动胶囊、深色模式下的用户消息气泡 |
| `--rm-bg-inset` | `#ededed` | `#0d0d0d` | 代码与工具输出、浅色模式下的用户消息气泡 |
| `--rm-text-primary` | `#1a1c1f` | `#ffffff` | 标题与正文 |
| `--rm-text-secondary` | `#1a1c1f` 74% | `#ffffff` 70% | 辅助文字、行副标题 |
| `--rm-text-muted` | `#5d5d5d` | `#9b9b9b` | 说明、时间戳、分组标题 |
| `--rm-text-faint` | `#afafaf` | `#5d5d5d` | 占位符、禁用图标 |
| `--rm-separator` | `#1a1c1f` 8% | `#ffffff` 8% | 行分隔线、细边框 |
| `--rm-accent` | `#1a1c1f` | `#ffffff` | 主按钮、发送按钮、焦点环 |
| `--rm-on-accent` | `#ffffff` | `#1a1c1f` | 主色上的文字与图标 |
| `--rm-running` | `#c2410c` | `#ff8549` | 运行中 |
| `--rm-decision` | `#7c3aed` | `#c27aff` | 等待授权或回答（桌面端 `--ds-purple`） |
| `--rm-on-decision` | `#ffffff` | `#1a1c1f` | `--rm-decision` 底色上的对勾和图标 |
| `--rm-success` | `#00802f` | `#40c977` | 在线、已完成 |
| `--rm-error` | `#d42a26` | `#ff6764` | 失败、已撤销、危险操作 |
| `--rm-link` | `#1c64c8` | `#63a8f8` | 仅用于消息正文里的链接 |

提示条和标签的语义底色为对应语义色在 `--rm-bg-surface` 上叠加 10%（浅色）或 16%（深色）。
主题跟随系统外观，App 内不提供主题切换。`theme-color` 和原生启动页在两种外观下都使用
`--rm-bg-page`（替换 `#0b0f14`）。

### 5.2 字体排版

字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC",
"Hiragino Sans GB", "Segoe UI", Roboto, "Noto Sans CJK SC", "Microsoft YaHei",
sans-serif`；等宽：`ui-monospace, "SF Mono", Menlo, Consolas, monospace`。
不打包网页字体（CSP 只允许同源字体，且系统字体对中文渲染最好）。

| 角色 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| 大标题 | 28 / 34 | 700 | 未滚动时的 S4 标题、S1 与结果页主标题 |
| 标题 | 17 / 22 | 600 | 导航栏标题 |
| 小标题 | 16 / 22 | 600 | 行标题、卡片标题 |
| 正文 | 16 / 24 | 400 | 消息、表单输入（16 px 可避免 iOS 聚焦时缩放） |
| 说明 | 15 / 22 | 400 | 卡片和弹层里的解释文字 |
| 副标题 | 14 / 20 | 400 | 行副标题、状态行 |
| 脚注 | 13 / 18 | 400 | 分组标题、帮助文字、时间戳 |
| 标注 | 12 / 16 | 500 | 标签、徽标、排队计数 |
| 等宽 | 13 / 20 | 400 | 工具名、工具输出、票据和 key 输入框 |

所有字号用 `rem` 表示，以便跟随浏览器和系统的文字大小设置缩放。文字放大到 200% 时页面不得
出现横向滚动（代码块可以在自身内部滚动）。

| 令牌 | 取值 | 用途 |
|---|---|---|

| 页面边距 | `max(16px, env(safe-area-inset-left/right))` | 页面左右内边距 |
| 分组间距 | 24 px | 分组之间；分组标题与分组之间 8 px |
| 卡片内边距 | 16 px | 分组行与卡片 |
| 行高 | 单行 52 px，双行 64 px | 列表行 |
| 触控目标 | 最小 44 × 44 px | 所有可交互元素，包括图标按钮 |
| 控件圆角 | 12 px | 按钮、输入框、选项行 |
| 分组圆角 | 16 px | 卡片和分组列表 |
| 弹层圆角 | 20 px（顶部两角） | 底部弹层 |
| 气泡圆角 | 18 px，尾角 6 px | 用户消息气泡 |

层级：浅色模式下，界面与页面只靠颜色区分（卡片不加阴影）。只有弹层、浮动的“新消息”胶囊和
底部输入区投影：浅色为 `0 -1px 0 var(--rm-separator), 0 8px 24px rgba(0,0,0,0.08)`，
深色只保留 1 px 顶部细线。

### 5.4 图标

与桌面端一致使用 Lucide（`07-ui-design-system` §7）：按钮和导航中 20 px、2 px 描边；行内
16 px、1.5 px 描边；空状态和结果页 48 px、1.5 px 描边。不用文字符号（`←`、`↻`）或 emoji
充当图标。图标默认 `--rm-text-secondary`；状态图标使用第 5.6 节的状态令牌。

### 5.5 动效

| 交互 | 时长 | 缓动 | 减弱动态效果时 |
|---|---|---|---|
| 按压反馈（透明度或缩放到 0.98） | 120 ms | ease-out | 仅透明度 |
| 提示条、标签、轻提示的出现与消失 | 200 ms | `cubic-bezier(0.2, 0, 0, 1)` | 立即切换 |
| 页面入栈与出栈（24 px 平移加淡入淡出） | 280 ms | `cubic-bezier(0.2, 0, 0, 1)` | 120 ms 交叉淡化 |
| 底部弹层打开与关闭 | 280 ms | `cubic-bezier(0.2, 0, 0, 1)` | 立即切换 |
| 状态点提醒 | 两个 1.6 s 周期后静止 | ease-in-out | 静止 |

只有表示正在进行的工作的指示器（流式回复、运行中的工具行、等待倒计时）可以在工作持续期间
一直动画，与桌面端 `07-ui-design-system` §4.5 的规则一致。

### 5.6 状态语义

电脑行、会话行、运行状态栏和时间线共用一套状态表达，且从不只用颜色传达状态。

| 状态 | 令牌 | 形状与动效 | 文案 |
|---|---|---|---|
| 在线 | `--rm-success` | 实心圆点 | 在线 |
| 离线或无法连接 | `--rm-text-muted` | 空心圆点 | 离线 |
| 运行中 | `--rm-running` | 实心圆点，呼吸两次；运行中的工具行显示转圈 | 运行中 |
| 等待决策 | `--rm-decision` | 实心圆点，脉冲两次 | 需要你处理 |
| 已完成 | `--rm-success` | 对勾 | 已完成 |
| 失败或已撤销 | `--rm-error` | 圆圈感叹号 | 失败 / 访问已撤销 |

## 6. 布局骨架

### 6.1 安全区（修复 D1 和 D2）

每条边的安全区只应用一次，由紧贴该边的元素负责，并且与常规内边距叠加——而不是替换常规内边距：

```css
/* 放在 @layer utilities 中，保证与 Tailwind 的先后顺序可预期 */
.rm-nav      { padding-top: env(safe-area-inset-top); }
.rm-gutter   { padding-left: max(16px, env(safe-area-inset-left));
               padding-right: max(16px, env(safe-area-inset-right)); }
.rm-dock     { padding-bottom: max(8px, env(safe-area-inset-bottom)); }
.rm-scroll-end { padding-bottom: calc(24px + env(safe-area-inset-bottom)); }
```

导航栏负责顶部安全区；底部固定区（输入框、决策区或底部操作按钮）负责底部安全区；没有底部
固定区的页面给滚动内容加 `rm-scroll-end`。`main` 永远不加顶部安全区。删除 `.app-safe-area` 类。

### 6.2 导航栏

- 顶部安全区下方高 44 px；背景为 92% 的 `--rm-bg-page` 加背景模糊；只有内容滚到其下方时
  才出现细分隔线。
- 左侧：返回按钮（chevron-left 图标，44 px 触控区，无障碍名称“返回”）。中间：标题（标题样式，
  单行，超长截断）。右侧：最多两个 44 px 图标按钮。
- S4 在滚动内容里使用 28 px 大标题，滚过之后收起为 17 px 的导航栏标题。
- 标题下可选一行副标题（脚注、弱化色），用于承载上下文，例如 S6 上的电脑名称。

### 6.3 底部固定区与键盘

底部固定区是页面列的最后一个子元素，吸附在底部。软键盘弹出时，固定区必须紧贴在键盘上方：
Android 和浏览器在 viewport meta 中使用 `interactive-widget=resizes-content`；iOS 使用
Capacitor Keyboard 插件的原生 resize 模式（决定 O2）。键盘动画过程中，时间线的滚动锚点
保持在底部。

## 7. 组件

以下组件替代现有 `Chrome.tsx` 中的基础组件，每个都是 `src/components/ui/` 下的小模块。

- **Screen（页面）**——包含导航栏、滚动区和可选底部固定区的列；负责第 6.1 节的安全区规则和
  640 px 内容宽度。
- **NavBar（导航栏）**——见第 6.2 节。
- **Button（按钮）**——变体：`primary`（主色填充）、`secondary`（界面色填充加分隔线边框）、
  `plain`（纯文字）、`destructive`（界面色上的错误色文字；只有在确认弹层里才使用错误色实心填充）。
  尺寸：`large`（52 px，全宽，用于唯一的主操作）、`medium`（44 px）、`icon`（44 px 正方形）。
  加载状态用转圈替换文字并保持宽度不变；禁用为 40% 透明度。
- **ListGroup / ListRow（分组列表 / 列表行）**——位于 `--rm-bg-surface` 上的内嵌分组列表，
  圆角 16，细分隔线从前置区域之后开始。行包含前置区域（状态点或 32 px 图标块）、标题、可选副标题、
  可选尾部（箭头、值或 44 px“更多”按钮）。可导航的行整行都是触控区。
- **SectionHeader（分组标题）**——脚注、弱化色、左右缩进 16 px，可选右侧纯文字操作。
- **StatusDot / StatusLabel（状态点 / 状态文字）**——见第 5.6 节。
- **Banner（提示条）**——导航栏下方的全宽横条，用于连接和数据新鲜度状态。色调分中性、运行中、
  错误三种，可带右侧操作。同一时间最多一条，优先级为错误、运行中、中性。
- **Callout（说明框）**——内容中的着色框，用于解释与周围内容相关的单件事（例如“这个问题只能在
  电脑上回答”）。
- **Sheet（底部弹层）**——带拖动条、标题和操作的底部弹层，用于操作菜单、确认和停止方式选择。
  可通过点按遮罩、下滑、Escape 或 Android 返回键关闭。
- **Toast（轻提示）**——在底部固定区上方显示 2.5 秒的临时确认（“已停止”“已忘记 MacBook”）。
  永远不用于需要用户处理的错误。
- **EmptyState / ResultState（空状态 / 结果页）**——48 px 图标、大标题或小标题、一段说明，以及
  最多一个主操作和一个纯文字操作。
- **Skeleton（骨架屏）**——`--rm-bg-inset` 色的静态占位块，带 1.2 s 透明度脉冲（减弱动态效果时
  取消），形状与被替代的行一致。
- **SecureField / TicketField（安全输入框 / 票据输入框）**——16 px 等宽文字；AccessKey 可切换
  显示；当 `navigator.clipboard.readText` 可用时，票据输入框右侧提供“粘贴”按钮。

## 8. 页面

### 8.1 S0 启动与启动失败

### 8.2 S1 连接

本机没有保存任何电脑时显示。

- 上半部分：64 px App 图标，大标题“在手机上接管你的 Agent”，说明“查看进度、批准操作、继续对话。
  任务仍在你的电脑上运行。”

- 底部固定区（拇指区）：

  - 不支持或无法确定账户模式：只有主按钮（大）“使用配对票据”。
  - 账户模式探测进行中（通常不到 1 秒）：按钮位置显示骨架屏，避免布局跳动。

### 8.3 S2 账户登录流程

在同一页面内完成的三步流程，导航栏下方有步骤指示（“登录 · 申请 · 确认”；当前步骤为墨色，其余弱化）。

**S2 登录。** 安全输入框“AccessKey”，可切换显示，帮助文字“仅用于本次登录，不会保存在手机上。”
底部固定区主按钮（大）“登录”，输入框非空时可用。纯文字链接“改用配对票据”。错误以“操作 + 原因”
显示在输入框下方。触发限流时按钮变为禁用的倒计时（“32 秒后重试”）。

**S2a 申请设备。** 一行紧凑的已登录信息（“已登录账户 1”，右侧纯文字按钮“退出登录”）。分组
“本账户下的电脑”列出每台主机，带状态点和一行合并了可用性与确认能力的副标题：“在线 · 可以批准
这台手机”“在线 · 需在本机逐台确认”或“离线”。“设备名称”输入框预填平台名称。主按钮（大）
“为这台手机申请访问”。如果没有任何电脑能确认，用错误色说明框替代列表说明，主操作改为“使用配对票据”。

**S2b 等待确认。** 居中显示：一个随剩余时间缩短的 96 px 圆环和 `mm:ss` 倒计时，小标题“请在你的
电脑上批准”，说明“在任意一台在线电脑上打开 Minih，批准“iPhone”。”下方是已收到请求的电脑列表。
底部固定区为纯文字按钮“取消”。临时读取失败时保持当前页面，显示中性提示条“正在重新连接…”，不重置圆环。

**S2c 结果。** 结果页的几种情况：

- 已收编：成功对勾，“已连接 3 台电脑”，主按钮“打开我的电脑”。
- 已超时：“没有电脑及时批准”，主按钮“重新申请”，纯文字按钮“使用配对票据”。
- 未送达（已批准但令牌未送达）：“已批准，但手机没能及时拿到访问权限”，主按钮“重新申请”。
- 已失效：“网关已不认识这个请求”，主按钮“重新登录”。
- 失败：“请求没有成功，手机上没有保存任何内容”，主按钮“重试”。

### 8.4 S3 配对票据

- 带两个编号步骤的说明框：“1. 在电脑上打开 Minih 的远程控制设置并生成配对票据（或运行

### 8.5 S4 我的电脑

- 大标题“我的电脑”；右侧（+）图标按钮打开弹层：“使用 Minih 账户登录”（仅在支持账户模式时出现）
  和“使用配对票据”。
- 一个分组列表。行结构：左侧 32 px 笔记本图标块，右下角叠加状态点；标题为电脑名称；副标题为状态行；
  可打开时右侧显示箭头，另有一个 44 px“更多”按钮。
- 状态行：“在线”、“检查中…”（骨架状态点）、“离线 · Minih 未运行或电脑已休眠”、“尚未同步 ·
  下拉刷新”（严格模式主机为“请在那台电脑上批准这台手机”）、“访问已撤销”、“这台手机已不再持有访问

- 点按在线行打开 S5。点按其他状态的行会在行内展开说明框，给出解释和唯一的修复操作（“重新申请”

- “更多”弹层：“刷新”、“重新申请”（仅尚未同步时）、危险操作“忘记这台电脑”。“忘记”会再打开一个

### 8.6 S5 会话列表

- 导航标题为电脑名称；副标题为电脑状态。
- 按项目分组，与桌面端侧栏一致：同一项目内的会话按最近活动排序，项目之间按各自最近一次会话排序。
  没有项目的会话、或所属项目已不在目录中的会话，归入末尾唯一的“其他”分组，因此不会有会话消失。
  没有会话的项目不显示，因为空标题是用户无法操作的东西。项目目录读取失败时列表保持扁平并全部归入
  “其他”，并用一行琥珀色文字说明原因。
- 行：左侧 12 px 状态位（第 5.6 节），标题最多两行（会话标题；没有标题时显示“未命名会话”，而不是
  原始 ID），副标题为“3 分钟前”，非空闲状态再附加状态词（“已停止”“失败”）。相对时间使用
  `Intl.RelativeTimeFormat`；超过 7 天显示日期。
- 加载中：六行骨架屏。刷新：下拉刷新以及回到前台时刷新；刷新不会重复发起它自己能回答的连通性探测，
  且每次进入只读取一次项目目录（两项均已实施）。
- 新建会话：`controller` 设备在分组标题处看到“新建会话”，打开 S5a（第 15.2 节）。记录的角色里没有
  `controller` 的设备看到的是原因而不是禁用按钮；角色字段出现之前写入的旧记录按“未知”处理并照常提供。
- 空状态：“这台电脑上还没有会话”，说明“在这里或电脑上开始一个任务，它就会出现在这个列表里。”
- 离线或加载失败：错误提示条带“重试”；保留上次加载的列表，但降低到 60% 透明度。
- 已撤销：结果页“这台手机的访问权限已被撤销”，主按钮“忘记并重新配对”。

### 8.7 S6 会话

**导航栏。** 返回按钮，标题为会话标题，副标题为电脑名称。

**连接提示条。** 实时连接时隐藏。`idle` → 中性“连接中…”；`retrying` → 运行中色“正在重新连接…”；
`exhausted` → 错误色“实时更新已停止”，右侧“重新连接”；`stopped` → 中性“已断开”；
`revoked` → 整个页面变为 S5 的“已撤销”结果页。`paused` 永远不显示，因为它只在页面隐藏时出现。
重新同步和回放不完整的提示使用中性提示条，沿用现有文案并按第 10 节改写。

**运行状态栏。** 运行进行中或排队时吸附在导航栏下方：状态点和文字（“运行中”“等你批准”“等你回答”
“已排队”），适用时显示排队标签（“排队 2 条”），右侧是次要中号按钮“停止”。点按“停止”打开弹层：

- “完成当前步骤后停止”——发送 `turn/stop`；主机完成当前助手回复或工具调用后结束本次运行。
- “立即停止”（危险操作）——发送 `turn/interrupt`；立即中止并取消排队中的运行。
- “取消”。

请求处理中时状态栏显示“正在停止…”，按钮禁用。运行结束后状态栏以 200 ms 动效收起，并用轻提示确认
（“已停止”“运行已完成”）。

**时间线。**

- 用户消息：靠右，最大宽度 85%，气泡为 `--rm-bg-inset`（浅色）或 `--rm-bg-raised`（深色），
  圆角 18，尾角 6 px。
- 助手消息：靠左，无气泡，全宽，按 Markdown 渲染（段落、列表、引用、标题、行内代码、仅限
  http/https/mailto 的链接、自带横向滚动代码块的围栏代码、横向滚动容器中的 GFM 表格），不含原始
  HTML、不加载远程图片。流式输出中尚未结束的代码围栏也照常渲染，因为读者看的是进行中的工作而不是
  成稿。实现与验证见第 15.5 节。由子代理发出的消息前加一行小字“来自 {agent}”。
- 思考：折叠的展开项“思考”（脚注、弱化色、箭头）。
- 工具调用：是一行紧凑的条目，而不是一张卡片。类别图标（读文件、列目录、搜索、写入、编辑、命令、网页、
  子代理、计划）、简短工具名、一句它作用于什么，以及状态标记。工具自己的输出从不作为这一行的文字——
  那是读者主动展开才看的东西。点这一行会在 `--rm-bg-inset` 中以等宽 13 号字展开输出，可横向滚动，
  最高 220 px。类别、摘要与整组文案都来自 `packages/shared/src/tool-presentation.ts`，
  与桌面端转录使用同一批函数，因此两端对同一次调用的描述一致。
- 连续的工具调用折叠成一行：图标、一句话（“4 条命令，编辑 2 个文件，写入 1 个文件”，
  最多三段以保证只占一行）、有失败时的数量、以及箭头。展开后逐条列出上面那样的行；
  再展开其中一条才显示它的输出。两层是手机的合适深度：第一次回答“这里发生了什么”，
  第二次回答“给我看那一条”。只有一次调用的组直接画成普通行，不做折叠。
- 系统与上下文压缩提示：两条细线之间居中的脚注（“上下文已压缩”）。
- 被截短的内容用标注样式的“已截断”标签标出。
- 运行失败：在该次运行末尾显示错误色说明框“运行失败：原因”。若唯一的原因是内部错误码
  （由 Host 自行结算的回合），只显示“运行失败”而不显示原因，协议信封永不渲染。会话头部用
  `session.turn.failedStatus` 标出结果（被取消的回合用 `session.turn.canceled`）。
- 滚动：页面打开时定位到底部；只有当用户距离底部 120 px 以内时，新内容才自动跟随；否则在底部固定区
  上方出现带向下箭头的浮动胶囊“新消息”。
- 加载中：三个骨架气泡；空状态：弱化文字“还没有消息”。

**决策区。** 有待处理的授权或提问时，在输入框上方显示决策卡片。两者始终同时可见：卡片高度上限为
`clamp(200px, 100dvh − 400px, 55dvh)`，超出部分在卡片内滚动；因此在 568 pt 高的屏幕上，
时间线仍保留约 110 pt，输入框不会被挤出屏幕。它是页面上最醒目的元素。

授权卡片：

- 头部：盾牌图标和 `--rm-decision` 色标题（“需要你批准”“计划授权”“目标授权”）、风险标签
  （低风险为中性、中风险为运行中色、高风险为错误色）；有多条待处理时显示“1/3”和前后切换箭头。
- 内容：工具名（等宽）、摘要（正文，最多八行，带“展开”）、子代理来源，以及按整分钟显示的实时过期提示
  （“5 分钟后过期”），最后一分钟改为显示秒数（“45 秒后过期”）。已过期的请求变为只读并显示“已过期”。
- 操作：同一行两个等宽中号按钮——左侧次要危险按钮“拒绝”/“驳回”，右侧主按钮“允许一次”/“同意”。

## 9. 通用行为

- **错误。** 每个用户可见的失败都写明操作和原因（沿用现有 `failureText`）。位置：字段错误放在字段下方，
  页面级失败放在提示条，操作失败放在该操作旁边。永远不用轻提示展示错误。
- **不做乐观更新。** 不提前显示成功。发出的消息以待确认气泡显示（60% 透明度、小时钟图标），直到主机回显；
  授权在主机处理完成前保持“提交中”。
- **回到前台刷新。** 回到 App 时重新探测电脑状态并恢复会话事件流（沿用现有 `visibilitychange` 处理）；
  只有恢复超过 800 ms 时才显示中性提示条“连接中…”。
- **无障碍。** 文字对比度至少 4.5:1，状态形状至少 3:1；每个图标按钮都有无障碍名称；每次入栈和出栈后焦点
  移到导航标题；运行状态变化通过礼貌型实时区域播报；新到的授权只播报一次；流式文本不逐字播报；选项行暴露
  单选或多选角色；所有手势（下拉刷新、下滑关闭）都有对应的按钮或菜单。
- **减弱动态效果与透明度。** 见第 5.5 节；设置 `prefers-reduced-transparency` 时，导航栏模糊改为不透明填充。
- **隐私。** AccessKey、票据和令牌不出现在结果页、轻提示或日志中；安全输入框关闭自动填充、自动纠正和拼写
  检查（保留现有行为）。

### 15.2 S5a 新建会话（问题：无法选择模型）

S5 之上一层弹层，四行，顺序就是真实的决定顺序：

1. **项目**——Host 的项目目录，隐藏已归档项目。只有一个可用项目时预填并直接显示为值；多个时打开列表。
   “添加项目”留在列表底部（沿用 `project/browse` + `project/register`）。
2. **模型**——该行显示将要使用的模型与供应方名称（“Claude Sonnet 5 · Anthropic”）。点开进入模型列表
   （第 15.3 节）。`model/list` 尚未返回前该行显示“电脑默认”，创建时不带模型——那本来就是 Host 会做的选择。
3. **模式**——`agent` / `plan` / `goal`，各带一行说明（“直接干活并改文件”“先出计划”“跑到目标或预算”）。
4. **权限模式**——`ask` / `accept-edits` / `auto`，措辞与桌面端一致。

主按钮“开始”，用这四个值创建会话，随后客户端打开该会话的 S6 并聚焦输入框。创建需要 `controller`；
只有 `viewer` 的设备看不到这个弹层（S5 把入口换成原因，与现状一致）。

状态：创建中（按钮转圈、所有行禁用）、被拒（`FORBIDDEN`、项目在此期间被删除的 `NOT_FOUND`、
模型在列表与创建之间消失的 `INVALID_ARGUMENT`）——一律显示在按钮上方并带上 Host 自己的原因，
弹层保持打开以便改。

### 15.3 模型列表与模型标识（契约补充）

当前 `session/create` 与 `session/configure` 已经接受 `providerId`、`modelId`、`thinkingLevel`，
但手机无从得知有哪些可选值，`RacpSession` 也完全不携带模型——所以既做不出选择器，
也做不出“这条会话用的是哪个模型”的标签。

**`model/list`**（`viewer` 角色，按 RACP-HTTP 路由表为 `GET /v1/models`）：

```ts
type ModelSummary = {
  providerId: string;
  providerLabel: string;   // 仅显示名
  modelId: string;
  label: string;
  thinkingLevels: string[];  // 按供应方公布顺序
  defaultThinkingLevel?: string;
  supportsImages: boolean;   // 第 15.4 节的判定依据
  isDefault: boolean;        // Host 为新会话选的默认
};
// { models: ModelSummary[] }
```

约束，按优先级：

- **只有元数据。** 响应里没有凭据、API key、base URL、代理、请求头或价格。Host 用启动回合时同一份
  目录构造它，并丢弃任何它不会打印在桌面端模型选择器上的东西。
- **每次进入读一次，不是每次输入读一次。** 列表很小且在一个会话生命周期内基本不变；S5a 在打开时读一次。
- **不在列表里的模型不能选，但列表里的模型不保证存在**——供应商可能在读取与创建之间被移除，
  因此 `session/create` 照旧校验，弹层显示拒绝原因。
- **已有会话。** `RacpSession` 增加可选 `providerId`、`modelId`、`modelLabel`、`thinkingLevel`，
  以便 S6a 显示会话跑在什么模型上。字段可选且只增不改：不发送它们的 Host 仍产出合法 session，
  客户端隐藏该行。
- **切换会话模型**走 `session/configure` 的 `providerId` + `modelId`（+ `thinkingLevel`），
  需要 `controller`，且**仅在会话空闲时**：桌面端本来就拒绝在回合运行中改模型，手机必须显示同一个原因
  （`AGENT_BUSY`），而不是看起来成功了。新模型不支持的思考档位回退到该模型默认值。
- **两端都要实现。** 桌面 Host（`desktop-host-operations.ts`）与 `agent-host-cli` 各自实现目录读取，
  共享契约与路由表新增该操作，Gateway 无需新代码（它按这两张表校验），但需要补一条
  `GET /v1/models` 与其他声明路由一样被转发的测试。

### 15.4 图片与文件（问题：无法发送）

协议已经定义了流程（第 10 节），但没有任何实现：Host 声明 `attachments: false`，
两个操作返回 `CAPABILITY_UNAVAILABLE`，`turn/start` 带附件直接拒绝。分两步，先小后大。

**第一步——内联，受一次请求的预算约束。** 小图片或小文本文件放进 `turn/start`，
这正是协议自己的第一类情形（“小文本与图片可以内联，只要整个请求低于 `maxPromptBytes`”）。

- 预算：整个 JSON-RPC 请求低于 `maxPromptBytes`（256 KiB），因此远低于 `maxFrameBytes`（1 MiB）。
  单次一个附件因此编码后最多约 180 KiB；输入框对更大的文件直接说出大小与上限，不做假的接受。
- 允许的类型由 **Host 嗅探内容** 决定：PNG、JPEG、WebP、GIF 图片，以及 `text/plain` 类文本
  （UTF-8、无 NUL 字节）。声明 MIME 与字节不符者拒绝，未知类型拒绝。第一步**不接受 SVG**
  （SVG 是脚本容器，客户端还得负责渲染）。
- 字节落在哪：Host 解码后写入数据目录下与会话绑定的目录，并转换成 runtime 已经接受的
  `AgentPromptAttachment`，因此 agent 从磁盘读取，runtime 无需新路径。
- **绝不接受路径或 URL。** Host 不接受 `file://`、绝对路径、远程 URL，也不接受“引用我电脑上的这个文件”：
  它没有收到的上传，它无法为其背书（第 10 节已禁止；第一步在 schema 层面继续禁止）。
- 清理：目录属于会话，随会话删除；失败回合从未引用的字节按 Host 现有的临时数据清理节奏回收。
- Host 声明 `attachments: true` 与 `maxInlineAttachmentBytes`，客户端无需猜预算。

**第二步——大文件经 Gateway 分块上传。** `attachment/create` 返回不透明 id 与一次性、短时、
绑定主体与会话的上传目标；`attachment/complete` 携带大小与 SHA-256；Host 校验两者后才标记 `ready`，
`turn/start` 只引用 ready 的 id。分块以 256 KiB 跨 Host link。Gateway 只在完成前暂存字节，
除大小外不做校验。两个上限决定这里的“大”：

- Nginx 为该源配置了 `client_max_body_size 10m`，因此第二步的上传在未单独提高该路由上限前按
  每文件 10 MiB 封顶——而手机相册选图后通常更小。
- 协议的 50 MiB 每附件上限仍然是上限，不是承诺。

**客户端（两步共用）。** 输入框里的回形针按钮打开一个弹层：“照片图库”“拍照”“选择文件”。
选中项以芯片形式出现在输入框上方（图片缩略图或文件类型方块、名称、大小、移除）；每个芯片有自己的状态——
准备中、就绪、太大（带上限）、失败（可重试）。仍有“准备中”的芯片时发送会把它们挂起等待，
存在“失败”芯片时禁止发送。时间线行内的缩略图打开可关闭的全屏查看器；文件芯片不可点击，
因为手机没有办法打开 Host 上的文件。

**原生权限。** 选择文件不需要权限；拍照需要相机，读相册需要照片图库。两条用途说明要加进
`Info.plist` 与 Android manifest 的对应项，现有 native-config 测试要认识它们。
权限被拒时在打开弹层的位置说明，并给出跳转系统设置的入口——绝不静默失败。

### 15.11 工具调用读作“动作”，而不是输出

手机端把每次工具调用都画成一张独立卡片：44 px 一行，状态图标、等宽原始工具名、以及工具自己输出被截成的一行。
连续十几次调用就变成十几张几乎一样的卡片——在一个一次只看得到几行的屏幕上，这是最宽、最高、信息量最低的内容。
输出是读者主动展开才看的东西，不该成为这一行的构成。

规则如下，而且用的是桌面端转录的规则，不是另写一套：

- **一套分类、一套摘要、一句整组文案。** 它们位于 `packages/shared/src/tool-presentation.ts`，
  桌面端转录也引用同一批函数（`toolIconCategory`、`getToolSummary`、`describeToolRun`、
  `groupConsecutiveToolRuns`）。两端对同一次调用的读法由构造保证一致，而不是靠约定。
- **一行 = 类别图标 + 工具短名 + 一句它作用于什么 + 状态标记。** 不显示原始输出。
  类别决定图标（读文件、列目录、搜索、写入、编辑、命令、网页、子代理、计划），
  读者在读到文字之前就先认出这是哪类工作。
- **连续调用折叠成一行。** 折叠时说明这一组做了什么，每种工作一个短句，最多三段以保证不换行
  （“4 条命令，编辑 2 个文件，写入 1 个文件”），有失败时再显示数量。
  展开后逐条列出上面的行；再展开其中一条才显示该次调用的输出。两层是合适的深度：
  先回答“这里发生了什么”，再回答“给我看那一条”。
- **只有一次调用的组画成普通行**，不做带单个子项的折叠。
- **全部走 i18n。** 短句键与失败数量都是九个语言目录里的条目，不用英文碎片拼句子。

验收：在 390×844 下，一组十二次调用从 14 行、827 px 的占位缩到 3 行、161 px，页面无横向滚动，
展开后每行仍保留各自的摘要。改前/改后截图对是证据；共享规则由
`packages/shared/src/tool-presentation.test.ts` 覆盖，桌面端原有的
`tool-display`、`tool-identity`、`tool-presentation` 三套测试保持不变——
“保持不变”本身就是这次抽取行为无变化的证明。

### 17.2 页面

两个页面取代 S5 上的分组。两者都只回答一个问题，都只有一个主操作，延续第 15.1 节已定的规则。

|---|---|---|---|

#### S5，一台电脑的项目

- 导航栏：电脑名，副标题＝电脑状态（用第 5.6 节的圆点与用词）。右侧：浏览器版本放刷新（网页版没有下拉刷新）。
  不使用大标题：栏里已经写了电脑名，页面直接从分区标题（“项目”＋数量）开始，而不是再来一个说同一件事的标题。
- 每个项目一张卡片，卡片之间 10 px。卡片三行：项目名与会话数；聚合后的状态胶囊；最近活动时间，右对齐、弱化。
- 没有待处理事项的项目不显示胶囊，改为一行中性文字（“没有需要你的会话”）；会话数始终显示，卡片不会只剩一个名字。
- 有待处理事项的卡片左边有一条 3 px 的 `--rm-decision` 竖条。竖条是第二个线索，绝不是唯一线索：旁边的胶囊用文字说了同一件事。
- **聚合在客户端完成。** `project/list` 返回 `{id, label, archived}`（`packages/shared/src/racp.ts:436`），
  `session/list` 返回带 `projectId`、`status`、`updatedAt` 的会话。按项目计数、取最新的 `updatedAt`、统计
  `running` 与 `waiting_permission`，都不需要新字段，也不需要第二个请求——两个列表本来就在这个页面上。
  唯一算不出来的是“有几条在等你**回答**”（§17.4.1）。
- **排序**：先按下面四档，再按最近会话时间。
  1. 至少有一条会话在等用户的项目；
  2. 至少有一条会话在运行的项目；
  3. 有会话但没有在跑的项目；
  4. 一条会话都没有的项目。

  第四档由同一个比较自然落到底：项目的“最近”取它最新的会话，而没有会话就没有最近。所以规则是一个比较器，不是四个分支。
  同档按名称排序，刷新两次顺序不变。
- **“其他”**——没有 `projectId` 的会话，或项目已不在目录里的会话——单独一张末尾卡片，标题“其他”，
  副标题“不属于项目的会话”。它是真实目的地（进 S5b 能看到它们），且永不上浮，一条游离的会话不会把真实项目挤下去。
  在这里也能新建会话：创建时不带 `projectId`，新建弹层的项目行显示“不属于任何项目”，而不是让用户挑一个文件夹。
- **没有会话的项目要显示**，这与第 8.6 节隐藏空分组不同：它现在是一个带操作的目的地（可以在那里新建会话），
  而不是一个用户无法操作的空标题。已归档项目仍然隐藏，同第 15.2 节。
- 状态：加载（三张形状像卡片的骨架，不是行骨架）；读取失败（错误横幅带“重试”，重试期间旧卡片保持 60% 可见，即第 8.6 节的规则）；
  项目目录读不到（仅靠 `session/list` 仍能出卡片，所有会话落到“其他”，并有一行中性文字说明原因）；
  一条会话都没有（空状态“这台电脑还没有跑过任何会话”，主操作“新建会话”）；访问被撤销（第 8.6 节的结果页，不变）。

#### S5b，某个项目的会话

- 导航栏：项目名作标题；副标题＝电脑与它的状态，因为只有项目名的话，从推送进来就答不出“这是哪台电脑”。
  右侧：`+`（新建会话，项目已预选），浏览器版本另有刷新。
- 分区顺序固定，空分区隐藏：“需要你处理”（待批准或待回答）、“运行中”、“最近”（其余，按新到旧）。分区标题带数量。
- 行结构：行首 20 px 状态位（§17.4）；标题最多两行；副标题＝相对时间、状态词或待处理胶囊、模型标签
  （`modelLabel`，宿主给了才显示）。模型标签先被截断，因为它是这一行里最不重要的事实。
- `+` 打开第 15.2 节的弹层，项目已填好并作为“值”显示而不是“选择器”，因为用户就站在这个项目里。
- 空状态：点名项目的空状态（“web 应用 还没有会话”）、说明“在电脑上开始的任务会出现在这里”的句子，以及底部主按钮“新建会话”。
  这一层比一个空标题真正有用的地方就在这里。

### 17.3 导航与返回

页面栈变成四层。`src/lib/screen-stack.ts` 增加两个页面类型，`previousScreen` 仍是唯一规则，
所以导航栏返回键、Android 硬件返回键、浏览器后退与 iOS 边缘滑动仍然不可能互相矛盾（第 4 节）。

```text
S4 我的电脑  >  S5 项目  >  S5b 某个项目的会话  >  S6 会话
```

- **只有一个项目时不当作列表。** 电脑只有一个可用项目时，点电脑直接进 S5b，S5 不进栈，返回就回 S4。
  这个跳过在导航发生的那一刻依据 S5 本来要渲染的数据决定（`session-groups.ts` 里的 `soleProjectForNewSession`
  已经在为新建会话弹层回答同一个问题），所以 `previousScreen` 永远不需要问“我上面原来有没有一层列表”。
- **只有一台电脑时不跳过 S4。** 连接、忘记、设置都属于 S4，所有关于这台电脑的失败也在 S4 解释。
  替代做法是：启动时如果恰好有一台**就绪**的电脑，直接打开它的 S5，并把 `computers` 先放到底下——
  返回仍然落在 S4，同时不必每次启动都穿过一个只有一行的页面。离线、未接受、已撤销的电脑不享受这个处理：
  启动页仍是 S4，因为那正是能解释问题的页面。
- **推送会恢复页面栈**（第 8.8 节的扩展）。负载里带 `hostId` 与 `sessionId`；应用在它本来就要读取的列表里找到
  这条会话的 `projectId`，把 `computers > projects > sessions` 写在 S6 底下。于是从推送进来的会话右滑返回，
  落在这个项目的会话列表，而不是电脑列表。只有一个可用项目时省略 `projects` 一层，与点击进来完全一致。
  如果这条会话还不在列表里（刚在电脑上新建），`projectId` 未知：应用打开 S6，下面只放 `computers > projects`，
  并在背后刷新列表——栈浅一点比编造一层更好。
- **两个根、一个栈**（[ADR mobile-direct-gateway-chat](/adr/mobile-direct-gateway-chat)）。
  原生构建的 `Screen` 增加 `chats`、`chat`、`chatArchive`、`modelGateway` 与 `settings`。
  `previousScreen` 保持纯函数，并对 `chats` 与 `hosts` 都返回 `null`，所以在任一根上按返回即退出应用；
  被推开的页面记录它必须回到的来源，正如 `projectSessions.viaProjects` 已经做的那样。
  切换标签在历史里替换根而不是叠加，因此返回从不会从一个标签走到另一个标签，被推开的页面也不显示标签栏。
  启动打开记住的根（第 4 节）：全新安装落在「对话」，对保存过电脑的安装升级后落在「电脑」，
  之后重新打开上次选中的根（`remote.last-root`）。S1 连接成为「电脑」根的空态，
  所以空的注册表或失败的配对永远不再拦住「对话」；点按电脑通知仍把根替换为「电脑」，
  并在会话下方重建 S4 ▸ S5 ▸ S6。浏览器构建保持单一的「电脑」层级，
  既不显示「对话」也不显示标签栏。
- 边缘滑动沿用第 4 节规则：手指从左侧 20 px 内开始、松手时超过三分之一宽度，就走同一个返回路径弹一层；
  以纵向为主的拖动交给列表自己的滚动。

### 17.4 一套状态词汇

六种状态、三种分量，每种一个形状、一个词。颜色用第 5.1 节已有的令牌，也就是桌面端的颜色
（`apps/desktop/src/styles/tokens.css`：`--ds-warning` 即 `--rm-running`，`--ds-purple` 即 `--rm-decision`，
`--ds-success` 与 `--ds-error` 同样对应）。

| 状态 | 依据 | 形状 | 用词 | 动效 |
|---|---|---|---|---|
| 等你批准 | `status === "waiting_permission"`，或 `planningState === "awaiting_approval"` | `--rm-decision` 的盾牌（或计划）字形＋待处理胶囊 | 等你批准 / Needs your approval | 1.6 s 脉冲，两次 |
| 等你回答 | 今天的列表里没有这个事实（§17.4.1） | `--rm-decision` 的问号字形＋同一个胶囊 | 等你回答 / Needs your answer | 同上 |
| 运行中 | `status === "running"` | `--rm-running` 的 8 px 实心点 | 运行中 / Running | 1.6 s 呼吸，两次后静止 |
| 失败 | `status === "error"` | `--rm-error` 的圆圈感叹号 | 失败 / Failed | 无 |
| 已完成·没看过 | `status` 为 `idle` 或 `aborted`，且 `updatedAt` 晚于本机记录的 `lastViewedAt` | 带外圈的对勾（用形状区分，不用透明度） | 已完成 / Finished | 无 |
| 空闲，或已完成且看过 | `status` 为 `idle` 或 `aborted`，且已查看 | 一个更弱的点 | 不用文字 | 无 |

以下规则在三个位置都成立（会话行、导航副标题、项目卡片）：

- **颜色从不单独表意。** 每种状态都把色相与字形、与一个词配在一起：胶囊自带文字，终态把文字放进行的副标题。
  一张黑白截图仍然读得懂。
- **只有“需要你处理”带底色。** 运行中与终态都是平的，正是这个例外让“需要你处理”有意义（第 3 节：决定优先）。
- **项目卡片只说两件事**：有几条会话在等用户（带数字的待处理胶囊）、有几条在跑（带数字的运行胶囊）。
  卡片上再多一个数字只会被当成噪音，终态的数量点进去就能看到。
- 动效遵守第 5.5 节：脉冲与呼吸各跑两轮就停；`prefers-reduced-motion` 下直接呈现静止标记；
  没有任何状态会“只要工作持续就一直动”——那是 S6 顶部的运行条专用。
- 无障碍：胶囊里的词就是可访问名称；行的 `aria-label` 读作“标题、状态、时间”，读屏不必依赖字形；
  当前屏幕上的状态变化通过第 9 节定义的礼貌实时区域播报一次。

#### 17.4.1 数据表达不了的那一个状态

`RacpSession.status` 曾经是封闭集合：`idle`、`running`、`waiting_permission`、`aborted`、`error`，
而输入请求只改**回合**状态，所以在 `session/list` 里一条在等你回答的会话和一条正在忙的会话无法区分。
这一点已在源头修好：**宿主现在直接在会话上报告 `waiting_input`**（协议 §5.1），
包括运行时仍认为 Agent 在跑的时候；问题全部答完后清除。列表因此不需要任何本地推断就能说“等你回答”。
有两点值得写清：

1. 本节早期版本描述的设备本地标记只保留作兜底：宿主版本较老时，由 `input.requested` 推送写入，打开会话时清除。
2. `waiting_input` 与 `waiting_permission` 是两个值，不是同义词：一个在表单里回答，一个是允许/拒绝，
   手机不能对两者打印同一个词。

“已完成·没看过”不需要改协议：它是设备本地的 `lastViewedAt`，打开 S6 时写入，存在注册表条目旁边。
它的边界要写进设计：这是按手机算的，重装应用后每条会话都算“看过”。

### 17.5 空、加载与失败

| 页面 | 加载 | 空 | 失败 | 离线 |
|---|---|---|---|---|
| S5 | 三张卡片形状的骨架 | “这台电脑还没有跑过任何会话”＋新建会话 | 错误横幅带重试，旧卡片保持变暗 | 第 8.5 / 8.6 节的规则，不变 |
| S5b | 六行骨架 | 点名项目，并提供新建会话 | 错误横幅带重试 | 旧列表保持 60%，同第 8.6 节 |

两个页面都不渲染“底下什么都没有”的标题，也都不显示自己无法兑现的控件（第 15.1 节的两条规则）。

### 17.6 通知

这条链路已经端到端存在，只是没开通。按顺序：桌面宿主在 `host.notify` 上报告四种事件
（`apps/desktop/electron/main/bootstrap/startup.ts`）；Gateway 做受众校验、去重、限速，再调用 APNs 或 FCM
（`apps/remote-gateway/src/push.ts`）；负载是一个封闭对象，只有类型、两个本地化键和若干 id
（`RacpPushPayloadSchema`，`packages/shared/src/racp-hostlink.ts:747`）；客户端按凭据注册令牌
（`apps/remote-web/src/hooks/usePushRegistration.ts`），并只凭 id 把点击解析成一个页面
（`apps/remote-web/src/lib/push.ts`）。让它一直黑着的，是 Gateway 上没配的一组参数，与 iOS 工程里缺的 entitlement（§17.7）。

#### 17.6.1 类型与文案

八个键名保持 `push.notify.<kind>.title` / `.body`（`pushKeysForKind`，`racp-hostlink.ts:768`），
因为它们同时会被生成到应用包的 `Localizable.strings` 与 `strings.xml`，应用关闭时由**系统**渲染。
只改它们的值。zh-CN 与 en 为准，其余七种语言从 en 翻译。

| 键 | 今天（zh-CN） | 建议 zh-CN | 建议 en |
|---|---|---|---|
| `push.notify.approval.requested.title` | 需要你处理 | 等你批准 | Needs your approval |
| `push.notify.approval.requested.body` | 有会话在等待你批准一项操作。 | 有会话在等你批准一项操作。 | A session is waiting for your approval. |
| `push.notify.input.requested.title` | 需要你处理 | 等你回答 | Needs your answer |
| `push.notify.input.requested.body` | 有会话在等待你的回答。 | 有会话在等你回答一个问题。 | A session is waiting for your answer. |
| `push.notify.turn.completed.title` | 回合已完成 | 已完成 | Finished |
| `push.notify.turn.completed.body` | 有会话的回合已完成。 | 有会话运行完成了。 | A session finished running. |
| `push.notify.turn.failed.title` | 回合失败 | 运行失败 | Run failed |
| `push.notify.turn.failed.body` | 有会话的回合失败了。 | 有会话运行失败了。 | A session's run failed. |

把“回合”改成“运行”是第 10 节自己的规则：面向用户的文案里不出现协议词汇。标题与正文都停留在类型层面，
所以两类请求和两类结果的口气不同，却不透露任何内容。

#### 17.6.2 正文点出会话，而标题不离开手机

负责人已于 2026-10-21 决定：显示会话标题，但标题不能经过 Apple。机制是 iOS 的通知服务扩展。
这里便宜的原因只有一个，值得记下来：Gateway 已经在发 `aps.mutable-content: 1`
（`apps/remote-gateway/src/push-providers.ts:162`），所以扩展一旦存在就会被调用，**触发它不需要改 Gateway**。

```text
宿主 --host.notify{kind, sessionId}--> Gateway --脱敏 aps--> APNs --> 手机
                                                                      |
                  服务扩展：GET {origin}/v1/sessions/{sessionId}
                  +-- 200 -> 正文 := 会话标题
                  +-- 超时 / 401 / 404 / 读不到凭据 -> 正文保持固定文案
                                                                      |
                                                                  锁屏
```

- **APNs 承载的内容不变**：`title-loc-key` 是类型标签，`loc-key` 是固定的正文键，另加 id
  （`sessionId`、`hostId`、`approvalId`）。Apple 只经手键名，不经手任何句子与标题。
- **扩展发哪个请求**：`GET /v1/sessions/{sessionId}`，即现有的 `session/get`——`viewer` 角色、只读一条、
  不含对话记录（`packages/shared/src/racp.ts:604` 与 `:716`）。它返回 `{ session: { title, ... } }`
  （`packages/racp/src/operations.ts:288`）；扩展只取 `title`，其余丢弃且不落盘。`viewer` 就够，
  所以只读手机也能拿到带标题的通知。
- **认证**：用 `hostId` 对应的设备令牌，从**共享的钥匙串访问组**读取，按原生 profile 发
  `Authorization: Bearer ...`。Gateway 源站也从同一个共享存储里取，因为扩展读不到应用编译时写死的常量。
- **时间预算。** 系统给服务扩展约 30 秒，然后调用 `serviceExtensionTimeWillExpire`。扩展自设更短的期限——
  **8 秒**（5 秒请求超时加余量）——并且两条路都要交付：超时、`401`、`403`、`404` 或读不到凭据时，
  用**未修改**的内容调用 content handler，用户看到的就是固定文案。
  `serviceExtensionTimeWillExpire` 也必须用手里已有的内容调用 handler，因为 handler 没被调用等于通知不出现。
- **钥匙串共享，以及它需要的迁移。** 今天的令牌存在 `@aparajita/capacitor-secure-storage`
  （`apps/remote-web/src/lib/native-secure-store.ts`），它是 Capacitor 背后的 KeychainSwift，**不设访问组**——
  插件源码从不设置 `kSecAttrAccessGroup`，条目落在应用私有组里，另一个进程读不到。迁移因此要写清楚，但很小：
  1. 两个 target 都在 entitlements 里列出 `keychain-access-groups` =
     `$(AppIdentifierPrefix)group.app.minih.remote`，并都带 App Group `group.app.minih.remote`；
  2. 应用按每个已配对电脑，往该组写一条通用密码项 `{ origin, hostId, token }`，
     可用性 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`（与应用现有保护等级一致）；
  3. 写入时机：配对、账户采纳、`ready()`；删除时机：忘记电脑、退出登录。应用自己的存储仍是唯一事实来源，
     镜像写失败只损失标题，不影响应用运行。

  这是扩展唯一真正约束客户端的地方，所以它是独立的一步（§17.9 P3），并有自己的测试：
  被忘记的电脑必须失去镜像项，退出的账户设备也必须失去。
- **扩展遵守的一个开关。**“显示会话标题”是 App Group `UserDefaults` 里的一个标志。关闭时扩展根本不发请求。
  关闭是一种隐私选择而不是降级，所以设置行要用一句话说明。
- **隐私边界性质不变。** 标题只在这台手机与用户自己的 Gateway 之间、走 TLS、由手机以自己的身份认证后传输。
  它不会进入推送负载、APNs 或 FCM 报文、Gateway 日志或审计记录。ADR 0331 决定 7 的脱敏规则因此完好无损，
  新的只是“客户端从哪里拿到这些字”。
- **分组。** iOS 的 `thread-id` ＝ 会话 id，同一会话的多条事件叠成一组；Android 用 FCM 的 `tag` ＝ 同一个 id。
  两者都由负载里已有的 `sessionId` 派生，所以封闭的负载 schema 不变——这只是 `push-providers.ts` 里的改动（§17.9 P2）。
- **角标。** 不发 `aps.badge`，这是有意的：正确的角标是“等**这个用户**处理的事有几件”，
  而 Gateway 与宿主都不知道用户已经看过什么，由 Gateway 编出来的数字几分钟内就会错。
  改为应用用它本来就算出的聚合值调 `UNUserNotificationCenter.setBadgeCount`（P3），打开应用时清零。
  这个边界要说清：应用关着的时候角标不动。要服务端算角标，得在 `host.notify` 里加待处理计数，那是协议改动，本轮不提。

#### 17.6.3 点击

`destinationForTap` 已经从 id 解析出页面；§17.3 补上要恢复的栈。两处补充：带 `approvalId` 时打开 S6 并滚到
决策区（第 8.7 节）；批准已在别处处理时显示“已处理”并在时间线里给出结果——第 8.8 节已经有这条规则。

#### 17.6.4 前台：应用内提示，不是系统横幅

iOS 插件在构建未配置展示选项时，
`willPresent` 本来就返回空的展示选项——`@capacitor/push-notifications` 返回空集，同时仍然通知 JS——
所以今天系统什么都不显示，缺的是 JS 侧的监听。因此客户端自己渲染提示，形式是居中弹窗而不是系统横幅：

- 应用订阅 `pushNotificationReceived`，渲染一个带遮罩的居中弹窗，挂在 `<body>` 上，页面任何层叠上下文都盖不住它：
  状态字形、类型作标题、类型自带的一行作正文、“查看”作主按钮、“关闭”作次按钮。点遮罩等同点“关闭”。
  它是 `role="alertdialog"` 加 `aria-modal="true"` 与 `aria-labelledby`/`aria-describedby`，
  读屏只读一次，焦点先落在“查看”上；
- 负载不带句子也不带会话标题（第 11.6 节），所以正文就是类型自带那一行；按钮打开会话，标题在那里；
- 待处理类（批准或回答）的提示一直留到用户打开或关闭它，因为那正是手机开口的原因；
  完成与失败类 6 秒后消失；
- “查看”推入 S6，恢复的栈与点击通知完全相同，两条路径不可能分叉；
- 不响铃、不振动。
- 用户当前就在该会话页面时不显示：决策区本身就是提示（第 8.7 节），在上面盖一个弹窗只会挡住用户正要看的东西。
  推送仍照常消费——`input.requested` 仍会把该会话标记为等待回答——角标也会更新。

2026-10-24 的用户决定取代了原先“导航栏下方提示条”的形态：那条会把安全区内缩算两遍——一次来自 `.rm-nav`，
一次来自它自己的固定偏移——于是文字上方空出一大块，而且作为一条窄带很容易被错过。居中弹窗正是用户要的；
它确实会盖住提示所讲的那个页面，所以文案只留一行，任一按钮都立刻清掉它。

#### 17.6.5 设置开关，以及它们放在哪

| 开关 | 由谁执行 | 代价 |
|---|---|---|
| 通知总开关 | 系统：只问一次，“不允许”对本次启动即为最终结果；该行显示状态（“已开启”“未允许”“这个 Gateway 没有配置推送”），被拒绝时提供打开系统设置的入口 | 无 |
| 只通知需要我处理的 | **Gateway**，因为系统已经投递的通知应用收不回来；现有注册接口上一个可选字段 | P2 |
| 显示会话标题 | **应用**，由扩展从 App Group 读取 | P3 |

按“尽量复用现有注册接口”的要求：`PUT /v1/push/registration` 增加一个可选字段
`onlyActionable?: boolean`，存进 `GatewayPushRegistrationRecord`，`PushService` 的类型闸门对设了它的注册
丢弃 `turn.completed` 与 `turn.failed`。路由、方法、第 11.5 节的受众规则、去重都不动；
不传这个字段的客户端行为与今天完全一致。该请求 schema 自身没有封闭对象约束，所以旧 Gateway 会**容忍**这个字段并忽略它——
用户体验就是一个什么都没做的开关。因此应用只在注册应答里回显了它时才显示这个开关，
并在 `RacpPushRegistrationResponseSchema` 里增加 `preferences?: { onlyActionable: boolean }` 专门用于回显。

首个版本的默认值：过滤器**关闭**，四种类型都发，因为在它显出吵闹之前，“你的活干完了”正是人们想要的通知。
打开过滤器只需一次点击。

#### 17.6.6 Android 与网页版

- **Android** 拿到同样的脱敏负载、四种类型、通过 `tag` 的按会话分组、点击目的地，以及同一条应用内提示（同一个 JS 监听）。
  它本轮**不**拿到会话标题：那里的等价物是一条 data-only FCM 消息加一条在应用被杀后仍要生效的
  `onMessageReceived` 路径，也就是常驻服务加可被唤醒的进程——比一个扩展大得多。
  Android 用户看到的是固定文案，标题开关在该平台直接隐藏，而不是显示成一个谎。
- **网页版**本轮仍然没有任何推送，并建议保持如此。Web Push 需要一对 VAPID 密钥（又一个运维机密）、
  一个 service worker，以及第二套凭据故事——cookie profile 的 `SameSite=Strict` cookie 不会被推送订阅的后台请求带上；
  在 iOS 上还要先把站点“添加到主屏幕”才可用，那是与“打开网址”不同的产品形态。
  ADR 0331 决定 7 把推送限定在应用内，本节不扩大它。

## 18. 日常使用的完整性与图片工作流

- 状态：可进入有界实施，2026-10-23。本文档改动不声称下列任何新行为已经发布或通过真机验收。
- 依据与权威：[Mobile completeness ADR](/adr/mobile-experience-completeness)。
- 优先级：本节取代新增量中重复选择模型、直接图片延后、仅复制式分享，以及仅空闲时才能本地删除的交互。
  它保留直连与远程各自独立的凭据、存储、权限，以及按会话执行的方式。其他章节不变。

### 18.1 对话与默认值

- 保留原生的“对话”和“电脑”两个根。“对话”有主要的“新建对话”操作、一等公民的“创建图片”操作，
  以及在同一份本地历史之上的“图片”筛选。H5 不获得直接访问模型账号的能力。
- 新建对话立即打开其输入框，使用该账号显式设置的文本默认值；没有显式默认值时，使用有效的上次选择。
  显式默认值缺失时必须重新指定；不存在静默的模型兜底。
- 首次出现的选择器要说明它是在设置默认值。“设置”分别提供文本默认值和图片默认值。
  更换某个会话的模型不会改变这些默认值，除非用户明确点了“用于新对话”。
- 从某个会话里“新建”会保留其草稿；被放弃的空白页面不增加历史行。重复点击不会产生重复的导航或付费请求。
- 远程项目的“快速新建”使用 Host 的默认值，而不是直连对话的设置。
  “带选项新建”保留模型/模式/权限；展示 Host 的实际取值。

*已被 §19.3 取代：* 原生版本有三个根。“对话”只列出文本会话，没有“创建图片”操作，也没有“图片”筛选；
图片工作放在“创作”里，在“对话”的选择器里选一个图片模型会切换到那个根。

### 18.2 会话与消息操作

- 直连会话行及其页眉上有一个可见的“更多”操作，打开同一组允许的重命名、置顶、归档/恢复、复制/导出与删除操作。
  长按和滑动是可选的快捷方式，绝不是必需的。对旧账号的内容保持只读，而不是把当前账号的权限套用到旧内容上。
- 删除要写明会话名称及其“仅在本手机”的范围。有进行中的工作时，先提供“停止”，再删除；只停止该会话，
  等待其收尾，并且只有在存储提交之后才移除该行。出错时内容仍可访问。
- 远程的永久删除/归档仍仅限所有者。给出准确的权限说明和需要在电脑上做的下一步；
  不要假装本地隐藏就删除了 Host 的转录。手机获得更宽授权需要另行决定。
- 增加逐条消息的“复制”。之后有界的操作是“重新生成最新回复”（保留之前的尝试）和“编辑并重新发送”
  （从前缀起建一个新会话，原会话不动）。两者都明确发起付费工作。这些直连操作并不意味着会修改远程 Host 的历史。

### 18.3 图片

- 支持图片的直连会话提供真实的选图输入、预览/移除，以及已实现处的显式相机拍摄。模型只收文本、或网关从未声明输入能力时，
  附件入口仍然保留，点按会说明是这两种里的哪一种：直接隐藏它看起来像功能缺失。能力未知不等于允许发送，两种情况都不发送、不丢草稿。
  MIME、大小或权限被拒绝时保留草稿。
- 用户自己发的图片，其附件没有 media id 时显示“图片 · 文件名”而不是留白：这一行取不到图，沉默会让人以为这条消息本来就没带图。
- 时间线上的图片使用有界的缩略图，并有加载中/不可用/出错状态。点按打开查看器，带关闭、适应屏幕、缩放/平移、保存与分享；
  返回先关闭查看器。图片加载过程中保持读者的滚动位置。
- 把直连的媒体与结果引用持久化到带版本的本地仓库。重新打开用已保存的字节，而不是已过期的 URL。未保存的结果要如实说明。
- 远程媒体来自 Host 经过认证的 session-media 读取，绝不使用手机提供的任意文件路径。旧版 Host 显示需要升级；
  文件缺失与访问被撤销有各自不同的状态。
- “创建图片”使用独立的图片默认值和经过验证的 Images 协议。起初每次明确请求只生成一张图，
  没有虚假的进度百分比，也没有未经验证的参数控件。结果出现在历史和“图片”中；文本模型默认值不变。
- 生成、保存、导出各有独立的成功/失败结果。持久化失败绝不会自动重复一次付费生成。
  “停止”不能承诺上游退款；“重试”是一次明确的新尝试。
- 保存与分享作用于已验证的字节，经由原生设施；在原生平台上，保存通过系统分享面板完成
  （例如在系统分享面板里选择“保存图片”），而不声称直接写入相册。用户取消不算失败，权限被拒要给出恢复指引，
  打开链接或发起网页下载绝不报告为已保存的文件。
- “编辑这张图”是后续增量，以经过验证的编辑契约为前提；原图保持可用，新的输出保留指向来源的链接。

*已被 §19.4 取代：* 图片生成已从“对话”里的“创建图片”操作和“图片”筛选，移到“创作”根；
“创作”写明每次请求一张图的规则，以及这个版本有意不提供的控件。

### 18.4 连续性、限制与验收

- 非空草稿、账号隔离和并发会话必须在导航之后依然保留。切到后台或连接丢失可能中断请求；
  恢复已保存的状态，而不自动再创建一次计费尝试。
- 可读的文本/Markdown 导出不是完整的备份/导入。“设置”要说明历史仅在本地，以及卸载/清除数据的风险。
  云同步和自动的桌面续接仍然延后。
- 键盘绝不遮住发送/停止；查看器与面板的返回顺序保持一致。
  在小屏/普通手机布局、大字号、浅色/深色以及本地化标签下验收变更过的路径。手势要有按钮替代，点击目标不小于 44 px。
- ADR 的 24 项矩阵是范围可追溯性，不是缺陷计数。AC01-AC16 定义可观察的验收；
  运行受影响的开发测试，而不是新增一场全仓库的发版仪式。原生的权限、分享与后台验收必须与 Chromium 验证分开报告。

实施必须先定稿增量的 RACP/安全线上细节，再做远程媒体改动，并通过迁移保持现有文本历史可读。
不得为了让 UI 通过而削弱角色或替换凭据。

  已有单元测试并通过类型检查，**尚未通过真机验收**。本节描述客户端当前的行为，
  对于它所取代的 §4、§5.1、§15.7、§17.6.5、§18.1 与 §18.3 的相应部分，本节是现状记录。
- 依据与权威：[Mobile redesign ADR](/adr/mobile-redesign)。
  ADR 保存着这项工作的两个起因缺陷的证据：模型按渠道级的协议并集来分类，以及用户旅程中有些步骤返回了却什么都没说。
- 范围：`apps/remote-web`，即 H5 构建与 Capacitor 的 iOS/Android 构建，外加 `packages/shared`
  里的一个增量字段（`MinihRouterModel.outputModalities`）。不改 Router，不加新端点，不加新的运行时依赖。

### 19.1 如何判定模型的能力

客户端里每一份模型列表都由同一个分类器投影而来（`src/lib/direct-chat/catalog.ts` 中的 `modelCapability`、
`resolveDirectModel`、`resolveDirectImageModel`）。它读取目录行的两个事实：模型声明自己产出什么
（`outputModalities`：网关逐模型声明的非空 `output_modalities`；网关发空数组或压根不发这个字段时，
用 `upstream_models[].catalog_reference.model.modalities.output`），
以及网关列出了哪些协议。

| 声明的输出 | 列出的协议 | 对话选择器 | 创作选择器 |
|---|---|---|---|
| 含 `text` | 某个对话协议 | 可用，`openai-completions` 优先于 `openai-responses` | 不列出 |
| 含 `image` | 任意 | 不列出 | 可用 |
| 含 `image` 与 `text` | 某个对话协议 | 可用 | 可用 |
| 含 `image`，不含 `text` | 任意 | 列为不可用（“图片模型——请在创作中使用”） | 可用 |
| 未声明任何输出 | 某个对话协议 | 可用 | 不列出 |
| 未声明任何输出 | `openai-images`，无对话协议 | 列为不可用 | 不列出 |
| 其他情况 | — | 列为不可用，并给出原因 | 不列出 |

- **渠道并集正是本方案所取代的陷阱。** Router 并不按模型声明协议：`/api/models` 用服务该模型的每个路由组里、
  渠道类型的客户端协议的并集来填 `protocols`，而 OpenAI 兼容渠道对它承载的每个模型都声明 `openai-images`。
  因此读取 `protocols.includes("openai-images")` 会把这类渠道背后的每个文本模型都归为图片模型：
  它从“对话”里消失，出现在图片列表里，在它上面新建对话会被拒绝，或被发往 `/v1/images/generations`。
  现在不再单独读取这个标志。
- **只要声明了 `image` 输出，就足以提供生成**，不论是否列出 `openai-images`：目录引用是更强的证据，
  端点在构建请求时才确定。
- **“两者都声明”在两份列表里是同一行。** 声明了 `text` 和 `image` 的模型，同时出现在“对话”选择器和“创作”里。
  运行哪种操作取决于用户从哪里开始，而绝不取决于名字：“对话”里的新草稿承载一个会话，“创作”里的请求生成一张图，
  已有的图片会话继续发送图片，因为 `resolveSendTarget` 从会话记录里读取那个标志。
- **名字与 UI 分类什么都证明不了。** 不查询 `model.category`：共享解析器在为桌面目录分组时，
  部分依据模型名字推导它，所以像 `qwen-vl` 这样的名字，否则会让一个网关实际通过 Chat Completions 提供服务的模型被禁用。
- **出图能力由网关逐模型声明（2026-10-24）。** 只有输出类型里含 `image` 的行才会出现在绘图选择器里；
  这一项由运营者在网关设置（`output_modalities`）；网关发空数组或压根不发这个字段时，客户端回落到上游目录引用
  ——空数组是“无法断言”，绝不是“没有任何产出”。
  未声明的行只要有对话协议就是对话模型，除此之外什么都不是：渠道并集不是关于产出的声明，
  `openai-images` 本身永远不能让一个模型变成图片模型。电脑端一直如此——绘图模型在设置里显式绑定、
  从不推断——手机端现在与它一致。
- **选择器列的是“可选项”，不是整份目录。** 对话模式只列能承载会话的，绘图模式只列网关声明能出图的。
  做不了当前操作的行根本不列出；绘图模式下如果一个声明都没有，就照实说明并指向网关的模型资料，
  因为只有那里能改。
- **没有静默兜底。** 已不存在、被禁止或无法承载会话的模型，解析为“不可用”，面板请用户重新选择；
  不会在另一个模型或协议上重试请求，因为那会对用户没有选的第二次尝试计费。
- **没有无理由隐藏的行。** 不可用的模型仍然列出，折叠起来，并带有三种原因之一：
  图片模型（请在创作中使用）、不是对话模型（embeddings、rerank、OCR），或是本客户端未实现的协议。

### 19.2 对话与图片的选择彼此独立

连接记录（`minih.remote-web.direct-chat.v1`，每个账号身份一份）保存四个模型字段，而不是两个：

| 字段 | 含义 |
|---|---|
| `lastModelId` | 文本会话上一次选的模型 |
| `lastImageModelId` | 图片生成上一次选的模型 |
| `defaultChatModelId` | 该账号显式设置的文本会话默认值 |
| `defaultImageModelId` | 该账号显式设置的图片生成默认值 |

- **一次性迁移，在读取时进行。** 已存的 `lastModelId`，若其缓存的目录行具备图片能力且无法承载会话，
  就移到 `lastImageModelId`，并在完成迁移的那次读取里把移动后的记录写回。已有的 `lastImageModelId` 绝不覆盖；
  缓存里没有的行保持不动，因为缺失目录不是证据；存储拒绝写入时，在本次会话内答案仍然正确。
- **拆分之前写下的记录是补种，而不是重置。** 在 `defaultChatModelId` 还不存在的地方，迁移后的对话模型成为对话默认值，
  所以展示给用户的默认值就是他们上次选的模型。
- **草稿的模型随导航走，而不随账号走。** 新会话以 `{ kind: "chat", conversationId, draftModelId }` 打开，
  界面把这个模型保存在本地状态里，直到第一条消息创建记录。因此从未发送的草稿不会改变下一次新建对话的起点。
- **“创作”选自己的模型。** 先用账号的图片默认值，再用 `lastImageModelId`，再没有就是没有——
  绝不替用户选一个对话模型。开始一次生成或选一个图片模型，会写入 `lastImageModelId`。
- **星标设置默认值。** 在选择器里，星标为当前分段写入默认值；不再可用的默认值会被报告为不可用，而不是被替换。

### 19.3 信息架构

原生版本有三个根，在栏里按此顺序排列，设置放在头像按钮之后，每个根都在其导航栏里绘制这个头像按钮：

| 根 | 内容 |
|---|---|
| 对话 Chats | 只有文本会话：置顶卡片条、带滑动与“更多”操作的最近会话行、归档链接，以及新建对话操作——它从账号的对话默认值（或上次的对话模型）开始，只有两者都不可用时才请用户选模型 |
| 创作 Studio | 图片生成：按天分组的结果画廊、实时的生成中卡片，以及提示词输入框（§19.4） |
| 电脑 Computers | 现有的层级：每行一台电脑，然后是它的项目，再是项目的会话，再是会话（§4、§17.2） |

- **设置不是根。** 它从任何根的头像推入，返回时回到打开它的那个根，因为在被推入的页面上按下标签，
  会把那个页面留在身后。
- **每次启动一个根。** 全新的原生安装打开“对话”。已持有电脑的安装在升级后的首次启动打开“电脑”。
  之后应用重新打开上次选中的根——这是 `localStorage` 里一个不含凭据的偏好（`remote.last-root`），
  并在首次启动时记录当时打开的根，使“回到我离开的地方”从第一次运行起就成立。存储被阻止时，偏好直接被忘记。
- **切换根是替换。** 复用上一个根所占的那个条目，所以“返回”绝不会在根之间来回切换，
  在根上按 Android 返回键会退出应用。被推入的页面从不显示标签栏。
- **不会在冷启动后恢复被推入的页面。**
- **通知入口不变。** 点按仍会用“电脑”替换根，并打开所指的会话，其下是如实的浅层页面栈（§8.8、§17.6.3），
  前台提示仍会打开同一个栈（§17.6.4）。浏览器构建仍不带推送。
- **H5 仍只有一个根。** 浏览器构建打开“电脑”，不画标签栏，也到不了“对话”或“创作”；直连模型账号仍仅限原生。

### 19.4 创作

“创作”是做图的地方。它列出账号的图片工作并发起新的生成；它不是换了个模型的聊天界面。

- **它列出什么。** 每一次产出了图片的尝试，外加同一提示词下最新的未完成尝试，由 `studioCards`
  （`src/lib/direct-chat/studio.ts`）从现有的图片会话中投影而来。卡片按日历日分组（今天、昨天，然后是日期），
  最新的在前，生成中的卡片钉在当天其余卡片之上，这样点按之后新请求立刻可见。同一提示词一旦存在更新的尝试，
  被取代的失败或已停止的尝试就被隐藏；已归档的会话不列出。每张卡片带有提示词、模型、状态
  （生成中、已完成、失败、已停止），完成时还带图片。
- **一次生成如何开始。** 底部的输入框发送一次请求：以 `operation: "image-generation"` 和 `openai-images` 协议调用
  `history.beginTurn` 记录这次尝试，然后在其上启动 runner。当前模型是标题下方的药丸，点它打开“创作”选择器；
  没有图片模型的请求会打开该选择器而不是发送，空提示词就地被拒绝。生成运行期间，同一个按钮变成“停止”。
  完成的卡片播放由模糊到清晰的显现动画，并有一条提示说明结果。
- **一张卡片提供什么。** 打开全屏查看器（复制提示词、用同一提示词再生成一次、删除）、停止正在运行的生成、
  在失败或已停止的卡片上用它自己的模型重试，以及带确认地删除图片；删除时会先停止仍在进行的生成。
  带图的卡片单独删除；失败或已停止的卡片连同它所遮挡的同一提示词的更早尝试一起删除——否则删掉后旧的失败会顶上来，
  看起来像删除没有生效。整条链在一个事务里完成（`history.removeFailedGeneration`），该提示词仍有生成在跑时整体拒绝删除。
- **它有意不提供什么。** 没有宽高比、尺寸、数量或质量控件：每次请求一张图，和请求适配器一直以来的工作方式一致，
  不虚构参数。不编辑已有图片。没有画廊范围的批量操作。同时能承载会话的模型在“对话”里提供对话，不在这里；
  在“创作”的选择器里选一个对话模型，会带着该模型的新草稿切到“对话”。

### 19.5 模型选择器

一张面板服务“对话”、“创作”和“设置”（`components/ModelSheet.tsx`，基于 `src/lib/direct-chat/model-picker.ts`），
它始终处于两种模式之一：

- **顶部的对话/图片分段控件。** 模式决定运行哪个分类器，所以同一份目录产生两份不同的列表：
  按厂商分组的对话行，或网关声明能出图的那些图片行。
- **搜索**，覆盖模型 id 和厂商。
- **按厂商分组**，每个厂商用两个字母的字母标；没有声明厂商的行归入“其他”。
- **每行的能力标签**：对话、图片、视觉（来自网关的 `inputModalities`）。
  每行还显示其上下文窗口，以及网关声明了价格时的输入/输出价格。
- **只列可选项。** 做不了当前模式的行不列出，也不再有一个折叠的“不可用”区。
  绘图模式下如果网关一个都没声明，就照实说明“网关还没有声明能出图的模型”，
  并指向网关的模型资料——那才是能改的地方。
- **星标设置默认值**，针对当前分段，并有一条提示说明是哪个模型；星标绝不改变眼前这个会话或生成所用的模型。
- **跨根选择。** 在“对话”选择器里选一个图片行会切到“创作”；在“创作”的选择器里选一个对话行，
  会带着该模型的新草稿切到“对话”。

### 19.6 会话页眉状态条

远程会话的页眉展示桌面端为该会话展示的内容，是标题下方的一条标签条
（`src/lib/session-chips.ts` 中的 `sessionChips`），点按任一标签或信息按钮会打开会话信息面板。

| 标签 | `RacpSession` 上的来源字段 | 显示条件 |
|---|---|---|
| 模型 | `modelLabel`，缺失时回退到 `modelId` | 任一字段是非空字符串；同时存在 `thinkingLevel` 时，追加为 `model · level` |
| 模式 | `mode` | 取值为 `agent`、`plan` 或 `goal` |
| 权限 | `permissionMode` | 取值为 `ask`、`accept-edits` 或 `auto` |

会话记录里缺失的字段什么都不显示：没有占位标签，也不从消息文本推断取值。电脑名字旁的“实时”标记，
只在事件流打开时出现。手机不拥有的两项会话操作——删除会话，以及为整个会话授予审批——保持仅限桌面端，
并且各自在本来会提供它们的地方用文字解释：删除在信息面板里，“本会话允许”在审批卡片里。
不存在做不成事的按钮。

### 19.7 设置

一个页面，从任何根的头像推入。每一行都执行真实的操作；没有“以后再说”的副标题，也没有死行。

| 部分 | 由什么支撑 |
|---|---|
| 账号卡片 | 连接记录：密钥名称、掩码后的密钥、`access_key_id`，以及缓存目录中的模型数量（`buildAccountCardView`）。没有连接时它变成连接操作，或说明本构建没有模型网关。**没有余额**：`GET /api/auth/session` 只回答密钥身份，所以不为它显示任何东西 |
| 默认模型 | 一行对话、一行图片（`formatDefaultModelRow`），各自显示模型名与厂商，或“未设置”，或在已配置的默认值不再可用时显示“不可用”；两行都打开选择器 |
| 模型网关 | 已连接状态，显示网关根地址，以及先确认再删除的断开操作，解除绑定失败时就地报告；未连接时是连接操作 |
| 通知 | 经由 `describePushSettingsView` 取得的 `usePushRegistration` 快照：注册或注销本设备的总开关，每种状态一行状态说明（已注册、等待电脑、权限被拒、已停用、网关没有推送服务、仅原生、失败），一行写明网关及已注册凭据数量的诊断行，以及一行说明网关没有逐事件的过滤开关 |
| 外观 | `lib/theme.ts`：跟随系统/浅色/深色，立即生效，存于 `minih.remote-web.theme.v1`，`system` 实时跟随系统外观 |
| 历史 | 本手机上该账号的会话数量，以及一个写明账号的确认之后的清除；在回复仍在到达时，清除会被拒绝并给出原因 |
| 旧账号 | 本设备仍持有的只读范围，每个一行，作为只读历史打开 |
| 关于 | 构建时取自 `package.json` 的应用版本、当前网关来源，以及隐私政策链接 |

- **逐事件的通知开关并不存在，所以不画。** 注册路由只接受一个可选的 `onlyActionable` 过滤，没有逐事件的开关；
  这个版本不发送它，所以全部四种事件（审批、提问、运行完成、运行失败）都会送达，
  “设置”用一行话说明这一点，而不是展示不会改变任何东西的开关。
- **版本不会漂移。** `vite.config.ts` 读取 `package.json` 并定义 `__APP_VERSION__`；
  没有版本的清单会让构建失败，而不是交付一个空字符串。
- **只有政策有地址时才有隐私行。** 政策是仓库里的文档，不是已发布的应用能推导出的 URL，
  所以配置了 `VITE_PRIVACY_POLICY_URL` 的构建显示这一行，其他构建则省略它，而不是提供一个无处可去的链接。

### 19.8 视觉系统

极光玻璃（Aurora Glass），在 `src/styles.css` 里定义一次，通过 `components/ui/` 的基础组件使用，
所以各界面不再手写按钮、行和面板的类。

- **令牌。** 极光强调色 `--rm-accent-1/2/3` 与 `--rm-aurora` 分组，卡片的圆角范围直到 `--rm-radius-sheet`（28 px），
  带发丝细边框的玻璃表面（`--rm-glass`、`--rm-glass-strong`），以及状态令牌
  （`--rm-running`、`--rm-decision`、`--rm-success`、`--rm-error`）及其重新调校的取值，
  所以状态保持含义，不再依赖旧的灰色调色板。
- **深色优先，并有真正的浅色主题。** `:root` 带深色调色板；`prefers-color-scheme: light` 把它翻转，
  `<html>` 上的 `data-theme` 让“设置 ▸ 外观”里的显式选择胜过系统设置。同时设置 `color-scheme`，
  使表单控件和滚动条与之匹配。
- **玻璃用在有意义的地方。** 导航栏在其下方内容滚过 12 px 之前保持透明状态，之后变成模糊的表面；
  标签栏和输入框是同一种材质。极光渐变是强调——药丸边框、发送按钮、头像光环——而不是页面背景。
- **动效。** 一套关键帧：空状态和主视觉状态背后漂移的极光、弹簧式的面板进入、滑动的标签指示器、
  流式输出的光标辉光、发送→停止的形变、带由模糊到清晰显现的图片占位闪烁、滑动的行操作、状态脉冲和顶部提示。
  全部是 CSS；不发布任何动画库。
- **减少动态效果。** 一个 `prefers-reduced-motion: reduce` 块关闭所有动画和过渡，并把滚动行为恢复为 `auto`，
  于是只有布局会变。
- **该偏好是本地的。** 它是 `localStorage` 里一个不含凭据的值；存储被阻止或已满时，保留内存中的选择，并以 `system` 启动。

### 19.9 用户视角的旅程修复

- 在还没有消息的会话里更换模型可以生效，并且只改变该会话——不改变账号用于下一个会话的模型。
- 开始一个图片任务，不再把下一次新建对话挪到一个不能对话的模型上。
- 重试失败的图片生成，会重试这次生成，而不是什么都不做。
- 重新生成、编辑并重新发送与重试，要么执行，要么说明为什么不能。
- 重命名打开时带有会话当前的标题，文本一变化“保存”就可用，包括记录在面板之后才到达的情形。
- 复制失败会说明失败，而不是看起来像成功了。
- 归档一个仍在回复的会话，标签是“停止并归档”，删除它会先停止再移除记录；两者都只停止该会话，
  因有工作在进行而被拒绝的操作会写明原因。
- 被撤销的会话提供“忘记这台电脑并重新配对”，并立即离开该界面；如果忘记失败，原因会显示在它落到的电脑列表上。
- “设置”的每一行都会做点什么，每个可能失败的行都会说明什么失败了。

### 19.10 这个版本不做什么

- 账号卡片上没有余额，原因见 §19.7。
- 没有逐事件的通知过滤，`onlyActionable` 过滤也不对外暴露。
- 除非构建配置了其 URL，否则没有隐私政策行。
- 没有图片参数——宽高比、尺寸、数量、质量——“创作”里也没有图片编辑。
- 没有对新根的浏览器自动化：E2E-266 仍以 390×844 驱动 H5 客户端，没有扩展（§19 状态）。
  新界面依靠单元测试和 `apps/remote-web/design/prototype/redesign.html`。
- 没有真机验收。三个根在模拟器和真机上的运行、带真实键盘和安全区的面板，以及原生外观切换，
  仍需与 Chromium 验证分开另行报告。

### 19.11 目录的时效与如实的失败原因（2026-10-24）

- **目录会刷新，不再冻结。** 过去它只在账号连接时写一次、之后再也不读，于是网关已经下线的模型仍然可选，
  在它上面的每次请求都失败，用户也看不出为什么。现在三个时机重新读取：应用回到前台、打开模型选择面板、
  进入“对话”或“创作”根页面；一个共享节流把这些时机收敛到每分钟最多一次请求。读取失败时缓存原样保留，
  并用 toast 说出来，列表不会悄悄变旧。已不在目录里的模型会自然走到既有的“没有模型 → 选择模型”路径。
- **两个网关错误码有了自己的说法。** `no_available_candidate`（503）读作“这个模型当前没有可用的线路，
  换个模型试试”，`upstream_cooldown`（429）读作“这个模型暂时繁忙，请稍后再试”。真正的额度码
  （`access_key_rate_limited`、`access_key_cost_limit_exceeded`）保留原来的额度文案。对话与图片两条链路
  都从拒绝响应体里读这个码；旧记录里出现本版本不认识的 kind 时，仍回落到网关那句兜底文案。
- **拒绝是提示，不是错误。** 只有用户必须读的失败——未授权、图片校验、保存、复制、不属于本账号的作用域——
  才用时间线下方的红色提示框。确认与提示（切换模型、已在回复、请先停止、请先连接、还没有模型）走会自动消失的
  toast。“没有可用线路”的失败在重试旁边同时给出“换个模型”，因为对同一个模型重试不会有别的结果。
- **创作把未完成的卡片放到整宽。** 每个日期分组里，生成中、失败与已停止的卡片在顶部占整宽——生成中是 4:3、
  更大的转圈与两行提示词，失败是一行横排：左侧原因与提示词，右侧重试与删除。已完成的图片仍用两列瀑布流。

### 19.12 思考强度（2026-10-24）

会话可以说“让模型想多深”。两种会话都不会自己发明档位。

- **远程会话。** 信息面板提供 Host `model/list` 为该会话模型公布的档位（`thinkingLevels`），按 `off` → `max` 排列；
  模型一个档位都不公布时，整项不显示。显示的值是会话自己的 `thinkingLevel`；会话没记录时用该模型的
  `defaultThinkingLevel`——绝不凭空写成 `off`。改动是一次带 `thinkingLevel` 的 `session/configure`，
  在运行中或待决策时锁定，理由与模型行相同。新建会话在新建弹层里选档，默认取模型默认档；
  切换模型时，新模型也公布同一档就保留，否则落到新模型的默认档（新模型没有默认档时，
  用桌面同一个 `nearestSupportedThinkingLevel` 就近取值）。页眉状态条以 Host 的答复为准，
  `模型 · 档位` 在 Host 回复后立即更新。
- **直连对话。** 信息面板列出网关为该模型声明的档位（`reasoning_levels`：`none`、`minimal`、`low`、
  `medium`、`high`、`xhigh`、`max`、`ultra`、`persistent`，见运行时规格 §5），第一项是“默认”——
  即不发任何思考参数，并可带出网关自己的默认档（`default_reasoning_level`）。只列已声明的档位。
  选择记在会话记录上；该字段出现之前写下的记录读作“默认”。请求分别带 `reasoning_effort`（Chat Completions）
  或 `reasoning: { effort }`（Responses），图片生成两者都不带。切模型后，新模型没有声明的档位会被丢弃，
  并用 toast 说明。`none` 用桌面 `off` 的同一个词显示——同一个概念，两套词表——而在这套词表出现之前
  存下的值（比如旧的 `off`）读作“默认”，永不发送。
- 两套词表各自原样显示：远程会话用 Host 的阶梯（`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`），
  直连对话用网关的九个值（`none` … `persistent`）。两者都不是翻译文案——只有周围的词
  （“思考强度”“默认”“不发送”）是翻译的——也不互相映射。

### 19.13 移动端对话由运营者决定（2026-10-24）

网关可以为每个模型决定是否开放给手机，手机照办。

- `GET /api/models` 可能给每个模型带 `mobile_chat`。`false` 表示这个模型在本机的对话里不出现，
  不论它本来能做什么；`true` 时仍按 §19.1–19.5 的规则。完全不发这个字段的网关比开关更早，
  它的模型照旧可用：沉默不等于“一个都没开”，那样读会让开关上线当天所有手机的对话列表变空。
- 对话选择器只列已开放的模型。网关一个都没开放时，面板直接说明，并指出要打开哪个开关
  （模型资料里的「移动端可用」）——与“搜索无结果”“没有出图模型”的文案不同。
- 模型不再开放的既有对话仍可阅读；发送区给出“选择模型”并说明该模型没有开放给移动端。
  不自动换模型：换一个模型就是另一次付费请求。
- 这个标记只管对话。创作仍只读声明的产出（§19.1），所以只开放出图、没开放对话的模型照样出现在创作里。
- 它是“许可”，不是“能力”。它不会让一个文本模型看起来像纯出图模型，所以关掉它不会把用户记住的对话模型
  迁到出图槽位——运营者随时可能再打开的开关，不该改写已保存的选择。

### 19.14 会话清单（2026-10-25）

会话的任务清单属于会话本身，因此手机从会话记录读取（协议 §5.8），而不是解析
`TodoWrite` 调用。

- 输入框上方一条紧凑的清单条：进度计数（`2/4`）与进行中的那一项，只占一行并在
  过长时截断。点开用底部弹层显示完整清单，每行带状态标记（待办、进行中、已完成、
  已取消划线）。
- 计数与桌面端停靠面板使用同一条规则（`@minih-agent/shared` 里的 `todoCounts`）：
  已取消的行从分母中去掉，而不是算作完成，因此两端报出的「3/4」不可能不一致。
- 没内容就不画：不保存清单的 Host、没有任何行的清单、以及全部完成或取消的清单，
  一律不显示清单条——390 px 的会话没有空间常驻一份已完成的清单，而且已完成的清单
  也不是正在进行的任务。
- 清单条位于决策卡片之上：审批或提问是读者此刻必须处理的，任务是上下文。
- 更新通过 `session.changed` 到达。Host 已经替换掉的清单（`revision` 更低）会被
  丢弃，因此无论事件与快照以什么顺序到达，手机都不会显示一份倒退的清单。
- 需要 Host 发送该字段。较旧的桌面端不显示清单条，也不报错。
