# 项目归档：显式导出与导入

> **翻译说明：** 本页是与 [英文源规格](/spec/03-runtime/23-project-archive) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

状态：已实现由 Host 拥有的项目归档（版本 1）。

项目归档把单个项目或项目组打包成一个 ZIP 文件。它之所以存在，是因为云端
配置同步只承载全局配置（[22-config-sync.md](22-config-sync.md)）：项目的
文件、技能、MCP 服务器、指令、记忆与自动化都属于持有该文件夹的机器，因此
把项目搬到另一台机器只能靠一次显式导出和一次显式导入。

归档是一次迁移，而不是一种关系。导入之后两份副本彼此独立；此后任一台机器
上的修改都留在本机，直到再次显式导出与导入。

## 1. 所有权与边界

```text
Renderer → Preload IPC → Electron Main → host-core (project_archive) → filesystem
```

- Electron Main 只负责原生选择器：导出目标是保存对话框，导入是"打开文件"
  加"打开目录"一对对话框。它只把选中的绝对路径传下去，不做别的。
- Host-core 是权威方。它读取已注册的项目、解析项目组与有序根目录、校验归档、
  在暂存区落盘并发布副本，并写入应用托管的记录。
- Renderer 只显示进度、结果和 Host 的错误文案；它自身从不读写归档。

## 2. 内容

包含：

- 每个有序根目录下的全部常规文件，包括隐藏文件与 `.git`，并保留目录结构和
  根目录顺序。
- 项目记忆与组记忆（`projects`／`project-group` 记忆记录）。
- 组的指令文本。
- 绑定到该项目的自动化（`workspacePath` 指向该项目）。
- 项目技能、子代理以及插件提供的技能文件：它们是 `<project>/.agents/` 下的
  应用托管文件，因此随根目录文件一起搬运，由接收端 Host 重新扫描。
- 项目的 MCP 定义，以脱敏后的 manifest 记录形式携带（见排除项）。

刻意排除：

- 会话、转录、附件，以及任何其它运行时或设备状态。
- 全局设置、账户、模型供应商 API 密钥、OAuth 状态、插件二进制文件与插件
  权限授予。
- MCP 的 `env` 与 `headers` **值**。`<project>/.agents/servers/*.json` 会把项目
  MCP 定义及其密钥值存在一起，因此这些文件从不复制。manifest 携带定义本身
  （id、label、description、transport、command、args、url、timeout、enabled，
  以及已配置环境变量与请求头的**名称**），导入时以禁用且无值的方式重建，用户
  在目标机器上重新填写密钥。两侧都不信任对方：导出跳过该子树（比较文件夹名时
  忽略 ASCII 大小写，因此把名字写成 `.AGENTS/Servers` 的卷同样能被识别），
  导入则**拒绝**携带该路径条目的归档，手工改过的 ZIP 也无法把带密钥的定义写
  回项目。manifest 中的定义按可移植字段白名单读取，其 `env`／`headers` 映射
  一律清空，无论文件里写了什么。
- 符号链接。链接会被跳过并记入结果计数；链接指向的文件不会被读取，因此导出
  永远无法跟着链接跑出项目。接收端因此也不会创建链接，无法被诱导写出目标目录。

归档包含整个项目文件夹，其中可能含有用户并不想分享的文件（`.env`、凭据文件、
构建产物）。导出界面在用户选择目标位置之前会明确提示这一点。

## 3. Manifest

归档根部的 `manifest.json` 是唯一可信索引。版本 1：

```json
{
  "format": "minih-agent-desktop-project-archive",
  "version": 1,
  "createdAt": "2026-01-01T00:00:00+00:00",
  "name": "Workspace",
  "roots": [
    {
      "index": 0,
      "name": "frontend",
      "fileCount": 128,
      "totalBytes": 4096,
      "skippedSymlinks": 0,
      "skippedSecretFiles": 1
    }
  ],
  "group": { "instructions": "…", "memory": { "content": "…", "entries": [] } },
  "projects": [
    {
      "root": 0,
      "memory": { "content": "…", "entries": [] },
      "mcp": [{ "id": "server", "label": "…", "envKeys": ["TOKEN"], "enabled": false }],
      "automations": [{ "id": "…", "prompt": "…", "cadence": "daily" }]
    }
  ]
}
```

manifest 只携带相对身份：有序根位置与该文件夹自身的名字。归档里任何位置都不
写入源机器的绝对路径。文件条目位于 `roots/<index>/<relative path>` 之下，导入
时每个条目名都会按该布局校验。

`fileCount` 与 `totalBytes` 是归档的完整性声明：导出用写条目的同一次遍历填充
它们，若遍历期间文件夹发生变化则失败；导入会把每个根的实际解出条目数与字节数
与它们对比。被截断、被填充或被手工改过的归档会被拒绝，而不是被导入。

**名称的可移植性。** 归档会跨平台流转，因此名称按其在大小写不敏感、规范化不
敏感卷上的身份来比较：先做 Unicode NFC，再转小写。在这个键上碰撞的两个条目
——或两个根文件夹名——在导入时会被拒绝，即便本地卷恰好能把它们区分开，因为
在 macOS 或 Windows 上后者会静默覆盖前者，从而丢失一个文件。导出遵循同一规则，
因此它不会产出本版本自身会拒绝的归档。

## 4. 导出

1. Host 从已注册项目列表及其存储的组解析 `projectPath`，拒绝不是已注册项目的
   路径。
2. 它在状态锁内逐个根目录计数（文件、字节、跳过的链接、跳过的应用托管密钥
   文件）并收集应用托管记录，然后释放锁。
3. 它把 ZIP 流式写入目标旁边的临时文件，再重命名到选定路径。重命名会替换该
   路径上已存在的文件——确认覆盖由原生保存对话框负责——且不触碰其它文件。
   导出失败或中断会删除临时文件，并让已有归档保持原样。
4. 结果报告目标路径、逻辑名称、根目录数量、文件数量、总字节数与被跳过的链接
   数量。

目标位置不得位于该项目自身的任一根目录之内。

## 5. 导入

1. Main 传入归档路径与目标父文件夹。
2. Host 先读取并校验 manifest：格式、版本、根目录数量与顺序、根目录名（单个
   安全路径段、互不重复）、项目到根目录的引用、条目布局（只允许
   `manifest.json` 与 `roots/<index>/…`）、符号链接条目、应用托管的 MCP 定义
   条目、每条目声明大小，以及展开后的总大小。重名检测比较**规范化**后的路径，
   因此 `a//b` 不能冒充 `a/b`。在所有名称合格之前不会解出任何内容。
3. 它解压到 Host 数据目录下的暂存文件夹——位于目标之外——在流式解压时按条目
   强制声明大小，随后按 manifest 核对每个根的解出文件数与字节总数。
4. 只有到这时才检查目标位置：每个根会被重建为
   `<destination parent>/<root name>`。检查读取路径本身而不跟随它：已存在的
   符号链接、不是目录的路径、或非空目录都构成冲突，导入会在此停止。目录创建
   之后立刻复查，因此中途被换进去的链接无法接收解压出的树。放在所选父目录下的
   链接是真实的攻击面——`exists()` 会跟随它，随后每次写入都会落到它的目标，
   可能位于目标目录之外。
5. 它创建文件夹、把暂存文件移入位置（只有在重命名不可行时才跨卷复制）、注册
   项目、写入应用托管记录，并在归档含多个根或组配置时创建项目组。
6. 任何失败都会删除它创建的文件夹、注销它注册的项目记录并清理暂存副本——不
   留下半导入的项目。成功时同样清理暂存副本。

导入的自动化以禁用状态创建，由用户在目标机器上启用。导入的 MCP 定义以禁用、
无密钥值的方式创建。导入的内容从不执行，也从不被授予插件权限。

## 6. 限额

| 边界 | 取值 |
| --- | --- |
| 单个归档的根目录数 | 32 |
| 单次导入的 ZIP 条目数 | 200,000 |
| 单次导入的展开字节数 | 8 GiB |
| 单个条目的展开字节数 | 2 GiB |
| manifest 字节数 | 8 MiB |
| 根目录名 | 单个路径段，最多 128 个字符 |

导出与导入共用这些边界：导出会在写入任何内容之前拒绝自己无法再次导入的项目
（单文件、整个项目或条目数超限），两侧失败时都返回
`PROJECT_ARCHIVE_LIMIT_EXCEEDED` 并给出指明越界项的可读信息。

## 7. 错误与 IPC

| 前缀 | Renderer 错误码 | 含义 |
| --- | --- | --- |
| `PROJECT_ARCHIVE_INVALID` | `INVALID_PARAMS` | 请求或归档本身不可接受 |
| `PROJECT_ARCHIVE_CONFLICT` | `CONFLICT` | 目标文件夹中已有文件 |
| `PROJECT_ARCHIVE_LIMIT_EXCEEDED` | `LIMIT_EXCEEDED` | 归档超出某项边界 |
| `PROJECT_ARCHIVE_IO` | `INTERNAL` | 文件系统步骤失败；信息中给出路径 |

通道：`projectArchive/export` 与 `projectArchive/import`（invoke），以及请求
执行期间的 `projectArchive/event/progress`，载荷为 `{ phase, done, total }`。
两个请求都由 Host 拥有且没有墙钟预算，因此大项目可以在 Renderer 离开页面之后
继续完成。

契约位于 `packages/shared/src/types/project-archive.ts`，Host 实现位于
`crates/host-core/src/project_archive/`，主进程选择器位于
`apps/desktop/electron/main/ipc/workspace-ipc.ts`。

## 8. 验证

- Host 单元测试覆盖：单项目往返（文件、隐藏文件、`.git`、记忆、无值的 MCP、
  技能、禁用的自动化），含组指令与组记忆的组往返，无组文本的单根组，拒绝覆盖
  非空文件夹，目标根是符号链接或普通文件，路径逃逸／未知根／规范化重名／大小写
  与规范化碰撞／符号链接／应用托管密钥条目的拒绝，注入的 manifest 密钥，同时
  删除已导入自动化的回滚，manifest 计数不匹配，跳过源符号链接，经符号链接抵达
  根目录的导出目标，超限项目，文件按大小写碰撞的项目，以及不受支持的归档版本。
- 多设备 E2E 流程在一台设备导出、在另一台导入，并断言恢复出的文件与设置。
