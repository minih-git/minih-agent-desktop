会话缓存保活 · 目录

让宿主自己去刷新某个空闲会话的 prompt 缓存。请求不进对话、不跑工具、不写任何消息，只读一次用量就停；插件只负责什么时候问、什么时候别再问。

status: implemented · folder id session.keepWarm · 权限 session.keepWarm · 决策 ADR 0339

01这个文件夹覆盖什么

一次付钱但不进对话的模型请求，以及谁来决定它能不能发。插件拿到的是一个结论（已保活，或者被跳过的原因），不是一个可以强推的入口。

页面回答
requirements.html用户已定的规则、接口形状、场景、不做什么
data-flow.html谁把什么传给谁、过程中写到哪里、出错怎么回

02一句话形状

const result = await pi.session.keepWarm({ sessionId });
// { status: "warmed", usage, cacheReadRatio }
// { status: "skipped", reason: "session_busy" | "no_prior_request" | ... }
// { status: "failed", reason: "provider_error" | "aborted" }
会花钱。这是应用里唯一一条“用户看不见、但要付费”的插件能力。可见性由三处补上：输入区的会话级状态、按次落库的用量、以及设计里写死的上限。

03相邻条目

  • usage.listTurns — 保活用量不进这个轮次账本，单独记账。
  • events.on — 计时从 session:turnEnded 开始。
  • ui/composer — 开关和状态的落点。
  • runtime/turn-continue — 花钱就得可见那条原则，本 API 是它记录的例外。
