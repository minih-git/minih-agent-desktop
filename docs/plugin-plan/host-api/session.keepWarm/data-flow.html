status: implemented

01接口约定

面向内容
插件拿到一次请求的结论：status、reason、usage（各项 token、costUsd、durationMs）、cacheReadRatio。
插件能调pi.session.keepWarm；pi.events.on("session:turnEnded") 用来计时；pi.session.list/get 用来知道会话还在不在、模型是什么。
宿主组件ui/composer 的 composerControl 右侧位（props 带 sessionId）。
权限session.keepWarm（付费请求）；session.read（会话列表与模型）；renderer.extension（输入区控件）。

  • 计时基准。session:turnEnded 送到插件时开始计时；每次真实轮次结束都重新计时。到点时先看当前时间，再看计时器——Mac 睡醒后延后的定时器不会拿一个过期时刻去花一次钱。
  • 前缀指纹。一个轮次结束时（回答已进 transcript）把“协议 + 端点 + 服务商 + 模型 + 适配器收到的 transcript”做一次 SHA-256，每条消息按线上白名单投影（role、content、sections、toolsAdded、toolsRemoved、toolCallId、toolName、name、isError——系统提示在 sections，工具声明在 toolsAdded/toolsRemoved），记进 sidecar 进程的账本；保活请求用同一段代码重新组装前缀，指纹不同就 prefix_changed。在请求发出时记录是没有用的：那一刻 transcript 里还没有下一轮要接上的回答。
  • 用量。一次一行，写在 keep_warm_usage，不进 turns.usage_json；同时计入 token 用量历史，另带 keepWarm* 计数，便于区分。

03出错怎么办

  • 宿主拒绝。返回 skipped 与 reason，不抛错。插件按 reason 决定继续排期（忙）还是停下（其余）。
  • 没有提前用量的协议。openai-completions／openai-responses 只在结束时报用量，所以读到结束；输出上限仍是真实请求那个值（不调低，否则会改掉思考预算、破坏缓存），代价是只多付「Reply with OK.」这一句的回答。
  • 请求失败。返回 failed。宿主不重试；插件停下，因为失败也是一次付费尝试。
  • 用户发消息。保活被 abort，返回 failed/aborted；用户消息不受影响。
  • 会话被删。返回 runtime_unavailable，落库时因为会话已不在而不写行。
  • 插件停用 / 卸载 / 退出。插件清掉所有定时器；已落库的用量不受影响。

04不提供什么

  • 不提供“强制发一次”。没有绕过判定或跳过指纹守卫的开关。
  • 不提供自定义请求内容。追加的那句话是固定的，插件不能改一个字。
  • 不提供读取对话内容的通道。这个 API 只回结论与用量，不回任何消息正文。
  • 宿主保证：请求不改对话、不写 transcript、不触发事件与 hook；真实轮次永远优先。
  • 已接受代价：应用重启后指纹丢失，重建前的会话会被跳过。

06还没定的事

  • 输入区是否需要一个“本次会话今日累计花费”更长的时间窗（现在是当日）。
  • 是否给用户一个全局的“所有会话今日合计”视图；现在上限是每会话的。
  • 非 Anthropic 协议要不要做成“读到结束”之外的更好办法（供应商支持提前用量时）。
